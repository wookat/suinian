# 书签抓取器出网口径（audit-r269 P1-2 定稿）

结论：服务端书签抓取器对公网 URL 的主动出网**不是 SSRF 缺陷**，是「保存链接自动生成标题/摘要」
这一产品功能的必要代价。攻击者能获得的只是「有用户保存了指向我域名的链接」这一时间信号
（来源为 Cloudflare 出口 IP 的匿名 GET），不含任何用户标识。

固定口径（与实现一致，backend/src/linkmeta.ts）：

1. 抓取仅在用户显式保存链接类笔记时触发一次，不做周期性回访。
2. 请求不携带任何用户标识（无 cookie/token/用户 ID），UA 为通用浏览器 UA。
3. 仅允许 http(s) 协议；`file:`、`ftp:` 等一律拒绝。
4. SSRF 防护：初始 URL 与每一跳重定向（上限 3 跳）均校验；`FORBIDDEN_HOST_RE` 覆盖
   `localhost`、`*.local`、`*.internal`、`metadata.google.internal`；IPv4 私网/环回/链路本地
   段在 DNS 解析后拦截（R269 生产实测：127.0.0.1、169.254.169.254、`[::1]`、nip.io 变体、
   `file:///etc/passwd` 全部未抓取成功）。

维护约定：此项不再作为待修缺陷挂账；若未来抓取行为变更（周期回访、携带标识、放开协议），
须先更新本口径并重新过安全评审。
