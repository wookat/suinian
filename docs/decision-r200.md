# R200 修改轮决策记录（落实 audit-r199）

对应审查报告：`docs/audit-r199.md`（R199 终定 GO，无 P0/P1）。本轮清 1 个 P2 + 1 个 P3，其余建议逐条评估。

## 1. P2-1 整数金额前提问法零命中 → 修复（金额 token 收口 + 验证式是/否直答）

R199 §4 实测：「我最贵的一笔支出是 400 元吗？」把「400元」抽成主题词注入 `WHERE content LIKE '%400元%'`，正文「学费 400」不含该字样 → 零命中 → 答「没找到」（真值明明在库里，确定性路线自己否证自己）。小数形态（368.5 元）因「.」不在主题词字符集里侥幸正常。

修复（全部收口在既有 `ask.ts` 主题词提取/极值路由管道内，无新实体）：

1. **金额 token 不作主题词**（`AMOUNT_TOKEN_RE`）：`financeExtremeTopicTerms` 与 `subsetTopicExtract` 提取前统一剥除「数字+币种词」token（元/块/块钱/人民币/美元/美金/日元/欧元/英镑/港币/韩元及 ISO 代码），孤立纯数字残渣同样过滤（`PURE_NUMBER_RE`）。
2. **验证式前提解析**（`financeExtremePremise` → `FinanceExtremeQuery.premise`）：「…是 400 元吗」「…是不是 400」这类带语气助词（吗/么/嘛/吧）或「是不是/是否」引导的金额前提被解析为 `{amount, currency}` 随极值意图下传；无语气助词的裸数字（序数「第 2 大」、时间「2026年7月」）不误判为前提。
3. **是/否如实直答**（`buildFinanceExtremeAnswer`）：有前提时与精确查询选出的极值行比对（±0.005，带币种前提只比对应币种行），相符答「是的。」、不符答「不是。」并照旧给出真值+引用；多币种无法定位目标币种时不强判，只列事实。
4. **同根因家族——量词短语尾巴**（`QUANTIFIER_TAIL_RE`）：R199 同节观察到「车厘子买了几斤花了多少钱」→ 主题「车厘子买几斤」、「咖啡机除垢剂…一次用多少」→「咖啡机除垢剂一次」整串注入 LIKE 必零命中；剥掉尾部「（动词）+数量+单位」后留名词主题。「一次性纸杯」这类以量词开头的商品名不受影响（锚定串尾）。

回归：`backend/test/r200-fixes.test.ts` 锁整数×小数×币种词变体（元/块/块钱/人民币/美元）× 是/否两个方向 × 有无主题限定 × 序数/时间数字不误判 × 量词尾巴家族；全量 1204 测试通过。

## 2. P3-1 否定话术引入未出现实体 → 修复（确定性输出侧后校验）+ 残留论证

R198 已在 prompt 里约束否定话术只能复述问句/片段中出现过的实体，R199 §6 仍实测到残留（「没有提到手机壳是在**淘宝**买的」「没有提到具体是**人民公园**」——均未在任何来源出现）。结论：LLM 路径靠 prompt 无法保证 100% 服从，本轮改为**输出侧确定性收口**，不再追加 prompt 规则：

- `scrubUnsourcedNegations(answer, source)`（`ask.ts`）：在 `reconcileAskCitations` 同一收口时机（done 事件全文替换）扫描「没有/未/不曾 + 提到/提及/说明/…」否定分句，宾语切块后（剥功能字/疑问代词/引用角标/泛指属性名词）若含问句与召回片段中都不存在的 ≥2 字实体串，整个宾语改写为「你问的这个信息」——否定语义保留、编造实体确定性清除。
- 误伤面：同义改述实体被改写成通用指代，只损失具体性、不损失诚实性。漏判面：单字实体、恰好是原文子串的实体——两者均不构成「引入未出现实体」。转折后半句（「但 [2] 提到…」）不在否定分句捕获范围内，部分否认答案不受影响。
- 残留量化口径：该校验是确定性的，「否定分句宾语引入 ≥2 字未出现实体」这一 R199 定义的缺陷类在输出侧残留率为 0；prompt 层残留率不再单独量化（输出侧已兜底）。
- **肯定句金额编造补丁（本轮生产 QA 实测新发现）**：忠实性 30 问跑出「周末我做了什么」→「周六和周日各花 20 元买菜」（笔记原文只有「超市买菜花了 82.5 元」），属肯定句金额编造，不在否定分句捕获范围。补 `scrubUnsourcedAmounts(answer, source)`：答案中「数字+币种」token 的数值在问句与召回片段中都不存在时整句剥除（数字边界比对，20 不匹配 2026；千分位/尾零归一）；全剥空则回落诚实拒答通道给建议。不带币种的裸数字（年份/数量）不在管辖范围，不误伤。

回归：r200 测试锁 R199 两条生产残留原文 + 复述实体不误伤 + 泛指属性词不误伤 + 肯定句不受影响。

## 3. P3-2 暗色对比度 2 处 → 修复

- 金额徽章商家小字（`note-card.tsx`）：暗色下 `text-rose-400` + `opacity-80` 混色后 4.01:1 < AA 4.5:1；改为 `dark:opacity-100`（rose-400 全不透明对 #321d26 约 5.7:1 ✓），亮色维持原样（rose-600 余量充足）。
- 设置页注销等实底破坏性按钮（`ui/button.tsx` destructive 变体）：暗色 `--destructive` 偏亮（对白字 3.43:1）；实底按钮暗色压深到 `dark:bg-red-700`（#b91c1c 对 #fcfcfc 约 9.3:1 ✓）。不动 `--destructive` 变量本身——文本类 `text-destructive` 用法在暗色深底上恰恰需要偏亮的红。

## 4. P3-3 千条导入分拣积压 ~2.5–3h → 不改（论证）

R199 §7 实测积压单调下降、无卡死，约 5–7 条/分钟由每 10 分钟 cron 的分拣批量与上游 AI 限速共同决定。千条 zip 导入是一次性迁移场景，非常态负载；加大批量或并发会顶到 Workers CPU 上限与 AI 网关限速，换来的只是罕见场景的时长缩短，代价是常态路径的稳定性风险。导入回执已如实告知「后台分拣中」，语义无损。维持现状。

## 5. P3-4 问答长尾延迟（P95 5.4s、一次 20.6s 离群） → 不改（论证）

P50 3.3s / P95 5.4s 在流式输出（首 token 早于全文完成）下体验可接受；20.6s 离群为上游 LLM 单次慢响应，非本仓代码路径可控。在不换模型/不加缓存实体的前提下无高性价比收口点，维持现状、留观后续审查轮的延迟分布。

## 6. P3-5 时间过滤按记录时间而非事件时间 → 不改（论证）

R198 P3-3 已在所有确定性财务答案的口径行明示「时间范围按笔记记录时间划定，不按正文里写的时间」，语义诚实。改为事件时间需要对每条笔记做正文时间 NLP 抽取并回填，错误抽取会静默污染确定性聚合（比零命中更危险），且补记场景占比低。维持记录时间口径 + 明示。

## 7. auth_rate_limits 历史过期行 → 已有实现，无需再改

`sweepAuthRateLimits`（`auth.ts`，24h 保留期）已挂在每 10 分钟 scheduled 任务里，R199 观察到的历史行属于清理上线前的存量，随周期清理自然消失。无需额外动作。
