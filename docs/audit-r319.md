### 0.2 架构级答案：直答层要不要「一律占位」？

**回答：要做。直答层「逐字转写单条笔记正文」这个出口本身无法用判据保护——五轮（R314→R318）数据的形状完全一致：自造样本归零、独立盲造照漏，第六轮换基元不会不同**【推断，依据 §3】。真正的结构级选择只有两个，应二选一而不是再修词表：

1. **默认分拣（LLM triage + `detectSensitive` 正则兜底）已经是生产上真正起作用的凭证闸门**【实测确证 §3.3】：同一 22 条盲测凭证载体走默认入库路径，21/25 条笔记被自动标敏感（进不了问答），直答层凭证原样 **0/12**；而 R317/R318 沿用的 `skip_triage` 方法学量到的 8/22 是**关闭了这道闸门后的上界**。这意味着：(a) R318 §2 的「本机纯函数归零」与生产用户真实体感之间隔着一个没有被任何一轮写进承诺的 LLM 判定；(b) 承诺文案应如实写成「自动标敏感是主闸门（模型判定，可能误标 / 漏标），直答层判据是兜底」，而不是反过来。
2. **直答层一律不转写正文（纯路线 2 全量）**：单条直答也改为「一行概括 + 卡片」，与聚合出口同构（聚合出口 LCS8 = 0 已在四套语料 370 行上证明这条路在族外也成立，§4.1）。R318 §1 用善意成本否决了它（R309 善意语料 39/307 = 12.7% 命令备忘变占位，顶破 R310 `directChanged ≤ 12%` 断言；「命令就是答案，占位 + 点卡片对命令备忘不成立」）——这个反对是实的，本报告不否认。但要并列看到另一面：那个代价是「用户多点一次卡片」（卡片本就随答案展示），而继续改判据的代价是每轮一周、族外漏网率不动（§3.2 五轮数据）。这是产品取舍而非技术对错，建议 R320 先按 SOP-02 出设计论证（善意 307 条实测体验、「命令就是答案」类问题的卡片路径交互、R310 断言是否随之调整）再定，而不是默认继续第四轮判据改写。任何「只对 fold 命中的笔记不转写」的折中都不是结构级——fold 本身就是判据，未识别形态同样不会被 fold。
3. 若两条都不选，则只能接受「直答层靠识别、识别不保证」的现状，但**承诺文案不能再写「R318 之后把安全边界放在结构上」而不写清结构只在聚合层**（§7.2 逐句对照），也不应再开第四轮判据改写。

### 3.4 机理【推断，读 `prompt-armor.ts` + 本地探针直接调用】

- `credentialValueTokens(unit)` 只登记「`SUBJECT_EXTRA` / `KV_RE` 词表命中 + 连接位（`是 / ：/ = / →` 等）+ 邻接串」三者同时满足的 token；`credentialValueSpans()` 再对答案做 `foldCredentialFace` 归一化 + 派生形（倒写 / base64 / hex / rot13）比对。本地直接调用：C01 / C03 / C06 / C13 / C14 → `[]`；C05 → `["Nn5^bb1"]` 有登记，但本地探针与生产直答仍原样（占位未生效，原因未定位【未验证】）。**结论：基元 = 词表 × 连接位，词表外即漏**。
- 破坏侧 `DESTRUCTIVE_*` 四缝仍是「动词词表 × 资源词表 × 形态正则」。自然语言族只有中文（`CN_DESTROY_VERB` / 归零类动词枚举：删掉 / 清空 / 抹掉 / 格式化 / 干掉 / 推平 / 归零 …），「恢复出厂设置 / 重新初始化 / 下掉 / 别留备份」不在；英 / 日 / 韩无；PowerShell 动词无；`echo > file` 截断只列 `: >` / `cat /dev/null >` / 行首 `>`；文件载荷 `--file=` 不看。
- 五轮数据（R314 → R318）的共同形状：**每轮修改者自造的族外样本归零，下一轮独立盲造照漏**。这不是某一轮判据写得差，是「用判据识别凭证 / 破坏能力」这个问题本身在族外不收敛（known-issues §1 第一段其实已经承认）。
