## 1. P2-1 多行台账分拣漂移 → 修复（既有台账管道双收口）

生产 6/6 复现的两个漂移，均在 `triage.ts` 既有台账识别/金额管道内收口：

- **case B 回款台账 → data 无金额**：新增 `fixLedgerCategory` 后校验——仅当 (a) 模型未判财务分类、(b) `parseLedgerCore` 能解析出确定金额、(c) 全文只有单一方向的台账词面证据（收入向 `回款|收款|收入|入账|到账|进账|货款` vs 支出向 `支出|开销|开支|花销|消费|采购|购物|费用|账单`）三者同时成立时，才把分类收口成对应方向；金额随后由既有 `fixLedgerAmount` 锁定合计。模型已判 expense/income/transfer 时不动（R196「台账方向模型主判」口径不变）；双向证据并存或无证据时不猜。prompt 同步补收入向台账判例。
- **case A 正数退款行并入合计**：新增 `signedRowAmount`——台账明细行金额为正但名目含退款语义（`退款|退货|退回|返现|返款`）时取负冲减；显式负号行为既有路径，不重复取反。`parseLedgerCore` 合计、`inlineLedgerRows` 识别、`ledgerRowsMatching` 明细全部走同一符号口径。显式合计行仍以合计值为准。
- 锁定：`test/r206-fixes.test.ts` 16 例（生产原文双例 + 方向收口边界 + 负号不回归 + 合计行优先 + 明细/守卫口径）；eval 集补 4 例（收入向×退款行×分隔符×极值），与既有台账形态用例集合并。
