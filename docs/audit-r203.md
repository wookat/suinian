## 1. R202 复核（生产实测）

### 1.1 SW 失败横幅 + beacon 上报 + 自动重试【生产实测】

方法：全新干净 user-data-dir + 浏览器级 CDP `Fetch.enable` 拦截 `*sw.js*` 注入失败（沿用 R201 §1 方法），CDP Network 面板观察 beacon 请求。

- 横幅出现且为 R202 新文案「离线缓存不可用（Service Worker 注册失败），在线功能不受影响；会自动重试，也可刷新重试」✅（截图 sw_banner_blocked.png）
- beacon `POST /api/metrics/sw-error` 发出，payload 仅含 `{name, message, retry:0}`，无 token 无用户内容，响应 200 ✅
- t+30s 自动重试：第二次 sw.js 拉取 + 第二个 beacon（`retry:1`）✅
- **解除拦截后 t+60s 档重试注册成功 → 横幅自动消失（`BANNER GONE = true`）+ `serviceWorker.active = true`** ✅——R202 因 Chrome SW 注册队列 wedge 未能定论的项，本轮用全新 profile 且在下一档 tick 前解除拦截的方法绕开 wedge 后实证通过（截图 sw_banner_after_success.png）
- beacon 限频：同 IP 连发 8 次 → `[200,200,200,200,200,429,429,429]`，恰好 5/分钟 ✅
