### 1.2 多金额句式全形态 —— 11/12 通过，1 项发现新形态偏差

`【生产实测】` 12 个句式：我买单总额 / 我垫付总额 / 我请客总额 / 只付自己那份 / 总额+人均无付款人（含同构复测）/ 单价×数量 / 原价折后 / 含税不含税 / 年费分摊 / 人均×人数禁虚构 —— 11 项全部命中「本人实付」口径（如 `expense/900`、`expense/640`、`expense/480`、`expense/130`）。

唯一失败项：

```
输入：[QA-R217] 我先付了聚餐 480 元，其他人回我 360 元
期望：expense/480（本人实付，回收另记 income）
实测：category=transfer, amount=120, currency=CNY
```

**扩展验证（专项 6 例，`【生产实测】`）**：

| 句式 | 期望口径 | 实测 |
| --- | --- | --- |
| 我先付了聚餐 480 元，其他人回我 360 元 | expense/480 | **transfer/120（净额）** |
| 聚餐 AA，我先垫付 480 元，其他人收回给我 360 元 | expense/480（+income/360） | **income/120（净额且方向反转）** |
| 帮同事垫付门票 300 元，他微信转我 300 元 | expense/300 或净额 0 | **transfer/300** |
| 请客吃饭 620 元，大家说下次还我 | expense/620 | PASS expense/620 |
| 团建总共花了 1200 元，人均 300 元 | expense/1200 | PASS expense/1200 |
| 聚餐总额 800 元，我只付自己那份 200 元 | expense/200 | PASS expense/200 |

`【源码检查】` `fixSplitBillAmount()` 只在「人均/每人/每位 + 总额」模式下把金额纠回总额；`fixAaReimburse()` 要求「AA/平摊/人均/垫付」后 10 字内出现「收回/收到/到账」。「我先付…其他人回我」「他微信转我」这类**先付后收回/垫付全额回款**句式两条规则都不命中，模型自行做了净额化，导致本人实付被低估（480→120、300→净额化成 transfer/300 而非支出+回款两笔）。

**分级：P2-1（新形态，R215 P2-2 邻接残余）**。影响：台账「本人实付」统计在这类句式上低估或方向错误；不影响数据安全与可用性。

## 3. 语音观察项核实（纯噪音）—— 发现 P2-2

`【生产实测】` 用 ffmpeg 生成三个样本（白噪音 10s/0.8 幅度、粉红噪音 20s/0.9 幅度、纯静音 6s）上传 `POST /api/ingest/media`：

| 样本 | 转写 | 入库内容 | meta | 分拣结果 |
| --- | --- | --- | --- | --- |
| 白噪音 10s | `transcribed:true` | **「继续关注后续发展」** | `raw_transcript="Продолжение следует..."`, `transcript_suspect=true`, `logprob=-0.205` | **idea** |
| 粉红噪音 20s | `transcribed:true` | **「继续关注后续发展」** | `raw_transcript="Продолжение следует..."`, `transcript_suspect=true`, `logprob=-0.238` | **todo（生成了待办）** |
| 纯静音 6s | `transcribed:false` | 「【语音】转写失败，稍后可重发（silence.mp3）」 | `media_status="extract_failed"` | idea |

失败态与重试可见性 `【生产实测】`：

```
POST /api/notes/<静音失败占位>/retry-media  → 502 {"error":"重试仍然失败，原件已保留，可稍后再试","retryable":true}
POST /api/notes/<噪音幻听笔记>/retry-media  → 400 {"error":"该笔记无需重试"}
```

评估：
- **静音 → 失败占位 + 可重试 + 原件保留**，这条路径设计与体验都合理（回复文案「已记录（语音转写失败，已存占位，稍后可重发）」，语义诚实）。
- **纯噪音 → 未走失败/重试，而是把 Whisper 的幻听（俄语固定幻觉串 "Продолжение следует..."）经 LLM 纠错后变成一句**看起来完全正常的中文**「继续关注后续发展」入库**，其中一条还被分拣成 **todo**，在待办列表里产生了一条用户从未说过的事项。虽然 `transcript_suspect=true` 会在卡片上显示存疑提示，但：
  1. 内容本身不像乱码，用户很难判断这是幻听；
  2. 这类笔记**没有重试入口**（`retry-media` 直接 400），用户只能手动编辑或删除；
  3. 幻听内容会进入时间流、待办与问答召回语料。

`【源码检查】` `backend/src/media.ts` 的 `isTranscriptSuspectHeuristic()` 判据是乱码率、重复串、raw↔corrected bigram 相似度、大音频短文本。本例失败于最后一条的阈值组合：音频 30KB/60KB > 100KB 门槛不成立（30KB < 100_000）、corrected 文本长度 7 > 5、raw 长度 24 但 raw↔corrected 相似度低本应触发……实际 `suspect` 确实为 true（由低置信/LLM 判定命中），但**suspect 只影响展示，不阻止入库、不触发重试、不阻止建待办**。

**分级：P2-2**。建议方向（仅建议，本轮不改）：对 `transcript_suspect=true` 的语音笔记（a）禁止生成 todo/金额等强副作用字段，(b) 开放 `retry-media`，(c) 对已知 Whisper 幻觉串（"Продолжение следует…"、"Thank you for watching" 等）做确定性拦截转失败占位。
