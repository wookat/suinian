# R118 设计决策与修改说明

对应审查报告：`docs/audit-r117.md`（PR #137）。本轮为「审改分离」的改方：系统性权衡后统一实施，高内聚低耦合、如无必要勿增实体。

## D1 敏感信息粒度：整条加密 vs 字段级脱敏 vs 部分遮罩

### 背景（第三轮出现）

取件码、联系人电话这类「低危高频找回」信息被判 sensitive 后整条加密：问答、待办清单、今日回顾全部不可见——「张经理电话回访」连「下周二回访」的安排都被一起锁死。安全铁律（密码 0 泄漏）历轮全过，但可用性代价日益明显。老板尚未定口径。

### 三方案对比

| 方案 | 安全 | 数据 | 可回滚 | 复杂度/新实体 |
|---|---|---|---|---|
| A. 整条加密（现状） | 最强：密文整条不出库 | 明文完整保存在 content_enc，可解锁 | 天然可逆 | 0 |
| B. 字段级脱敏（分拣时抽出“凭据类”字段单独加密，其余明文） | 取决于抽取召回率——模型漏抽一个字段即明文泄漏，**fail-open** | 抽取错误可能割裂原文 | 需迁移已有密文，回滚成本高 | 新增字段抽取 prompt+存储结构（增实体） |
| C. 部分遮罩（明文存储+显示时遮罩 138****1234） | 明文落库，任何注入/越权即全量泄漏，**fail-open** | 无损 | 可逆 | 遮罩规则集（增实体） |

### 结论（保守可逆，等老板口径）

**维持方案 A 整条加密不动**（安全优先、不丢数据、代价最低），只修可用性中最痛的一点：**敏感 todo 的 due 提醒失效**。B/C 都把安全模型从 fail-closed 变成 fail-open，且各自新增实体，在老板未定「凭据类 vs 联系/时效类」分级口径前不实施；若后续拍板分级，方案 B 的抽取式分级可在 triage 层增量加入，本轮改动不构成障碍。

### 本轮实施（不增实体，纯查询口径放宽）

敏感笔记的 **title 本就是明文且在时间流可见**（分拣 prompt 约束标题/标签不携带秘密值），密文内容仍然绝不出库：

1. `GET /api/todos/today`（bridge 上午清单）不再排除敏感待办——列表项内容为占位符+明文标题，与时间流一致。
2. 今日回顾「悬置的待办」候选与展示不再排除敏感待办（点评只见明文 title/占位符）。
3. 推送提醒维持既有行为（敏感待办通知文案为「一条待办」，锁屏不露标题）。
4. 问答/搜索/随机漫步继续完全排除敏感内容（fail-closed 不变）。

回滚：还原三处 SQL 的 `is_sensitive = 0` 即回到 R117 行为，无数据迁移。

## P1 收支方向判定（系统性修复，非补一条规则）

三层修复：

1. **Prompt 显式方向判据**：新增「收支方向」段——钱出去（交/缴/付/花/买/充/续/还＋金额，即使句中有“学费/会费/房租”等收费名词）＝expense；钱进来（到账/收到/入账/卖了/退款/报销到账/发工资/给我转）＝income，附 6 条方向 few-shot（含「交学费 400」原始失败样本、「学生给我交了补课费」反向样本）。
2. **确定性兑底 `fixFinanceDirection`**（triage.ts）：仅当词面证据单侧明确（只有流出词无流入词，或反之）时翻转模型方向；两侧都有词（歧义）或都没词时不动，模型仍是主判——规则只做 fail-closed 兜底，不做主判。
3. **eval 语料固化**：triage-eval 新增 10 条方向易混语料（交/付/花/缴/还/卖/退/报销/工资/别人交给我）+ 未发生交费→todo，含金额断言。

## 6×P2 逐条处置

1. **财务 fail-closed 过度触发**：`financeAggIntent` 新增事实型问句检测（叫什么/哪几本/什么时候…）——复合问句（问名字+合计）不再被 fail-closed 吞掉，落回正常召回由笔记原文直答。纯合计问句行为不变。
2. **拒答建议漏主题笔记**：建议排序改为「主题词命中优先，语义分次之」（`askTopicTerms`/`noteHitsTopic`：从检索词剥掉时间/聚合/财务/语气词后剩下的才是主题词）。
3. **零召回误称「找到了相关的笔记」**：`not_in_notes` 口径新增主题词命中校验——召回集中无任何主题词命中时回落 `no_recall` 诚实口径；零召回建议列表宁缺毋滥，仅保留真命中主题词的笔记。
4. **事件判 todo（三轮同型，根治）**：prompt 新增「外部事件/公告不是待办」显式判据+判例；新增确定性兑底 `demoteEventLog`——完成式叙述（写完了/挂出了/搞定了…且无未来动作词、无 due）降级 idea，外部公告（定档/上映/发售…且不含“我”）降级 data；eval 固化 3 条基线（定档→data、含“提醒我买票”→todo、挂出了→idea）。
5. **media_skipped 重复计数**：跳过计数收敛到 `storeMedia` 单点（父笔记被跳过的媒体因无 idMap 映射自然落入 skipped 分支），笔记循环不再预计，重复恢复不再翻倍。
6. **暗色滚动条**：`index.css` 补 `color-scheme: light/dark`——系统控件（滚动条等）跟随主题，作用于全站所有滚动容器而非单点补丁。
