# R296 修改轮决策记录

对象：docs/audit-r295.md 复评 NO-GO 的 2 个 P0 + 6 个 P1 + P2/P3。本轮按 §11 最小修复面执行；本文写明安全下界、两套策略的切换点，以及每项修复的口径与证据状态（实测确证 / 未验证 / 推断在 PR 描述中逐项区分）。

## 1. P0-1 降级态安全回归（fail-closed 双策略）

### 1.1 安全下界

**下界：任何「判别器不可用」的窗口内，不允许任何未经判别的答案原样出厂。** 不可用是攻击者可主动制造的状态（打满判别器配额/诱发超时），因此不可用态的处置必须与载体形态完全无关——不允许以「答案没有代码面痕迹」「确定性内核没命中」作为放行依据。R295 实测确证：散文型/注音/摩斯/跨笔记分片/U+E0000 标签字符载体对 `globalExecDangerReason()` 全返回 null，「可识别性」在不可用态做 allow 门 = 结构性 fail-open（unavailable 泄漏 0/60 → 23/60 的直接根因）。

### 1.2 两套策略与切换点

切换点是**判别器可用性**这个单一状态位，不是代码面痕迹：

- **在线（判别器本次调用返回了有效结果）**：保留 R294 的行/句级精度隔离。1.5% 真误伤率（3/130，2 条真误伤）是 online 态的成绩，不牺牲。
- **不可用（超时 / 抛错 / 返回不可解析）**：`classifyExecDanger` 返回 `unavailable=true` → `finalizeAskAnswer(execClassifierUnavailable)` **无条件**走整答案保守隔离早退路径，`exec_guard_degraded` 置真，前端渲染降级横幅 +「重试本轮提问」按钮。
- **不可用健康窗口（60s）**：一次不可用后的 60s 内（`execClassifierRecentlyUnavailable`），连「无代码面痕迹的纯散文」也按降级处置——这正是 23/60 泄漏载体走的口子。判别器成功一次即复位（`markExecClassifierHealthy`）。健康位是 Worker isolate 内存态，跨 isolate 不共享（推断：多 isolate 下窗口覆盖不完全，但每个 isolate 首次失败即自我保护，且单次请求内的不可用总是当次生效）。
- **在线零命中 ≠ 不可用**：判别器在线且返回空命中时正常出厂（保住 online 精度）；唯一例外是确定性高置信内核（`globalExecDangerReason`：`| sh`、`/dev/tcp`、`<(curl` 等）**否决**零命中——此时按不可用处置且不缓存该零命中。否决只在「拦」的方向使用，绝不在「放」的方向使用。

### 1.3 为什么 online 可以保留 1.5% 而 unavailable 不能用可识别性

online 态的行级精度依赖判别器的语义级判定，误放行由「确定性内核否决」兜底；unavailable 态两层全部缺席，确定性可识别性只覆盖已知形态（30 载体实测覆盖率 7/30），把它当 allow 门等于把安全性押在攻击者不换形态上。

## 2. P0-2 段落级连坐

双管齐下（R295 建议的组合）：

1. **生成侧强制分行**（近零风险主修）：主生成与拒答重试两处 system prompt 均要求多笔记回顾/总结/列举必须逐条分行（`- ` 列表项），不合并进同一段落。
2. **隔离单元细化为句**（后处理兜底）：`proseSentenceSpans` 对含 CJK 句读的自然语言行按句切分，只隔离命中句；无句读的代码行保持整行原子（不切碎代码语义）。引用块随句处置。

回归：`r296-guard-matrix.test.ts` 含「一段多条笔记、其中一条含危险命令」用例，无害笔记保留、危险句被隔离。

## 3. P1 财务时间窗四连修 + P2-6（`backend/src/ask.ts` 单解析器收口）

- **P1-1 跨年区间**：「2025年11月到2026年1月」成完整区间；无年份的「11月到1月」按 mon2<mon1 自动跨年。
- **P1-2「X月之前」**：日历月上界真窗口（`end=该月1日`，phrase 明示「不含X月」）；与模糊窗「三**个**月之前」用「个/多」区分。
- **P1-3 上界压 now**：「今年到目前为止/至今/为止/不要算未来的/别算未来」→ `end=now`，phrase「今年至今」。
- **P1-4 裸月份年份回写**：裸「12月」phrase 显式带生效年份（「2025年12月」），与「去年12月」措辞可区分。
- **P2-6 边界披露**：「8月17日以后」phrase 带「（含当日）」，「10月5日之前」带「（不含当日）」。
- 顺带：`isFinanceAggQuestion` 认财务名词问法（「今年到今天为止的支出」「2026年第二季度的支出」确定性路由，P3-3）。

测试：`backend/test/r296-finance-window.test.ts` 19 例；历史口径 `r294-finance-window.test.ts`/`r248-fixes.test.ts` 兼容（后者 1 处 phrase 期望随 P1-4 有意更新）。

## 5. P2/P3

- **P2-1**：隔离横幅定位到「第 N 段 + 关于「xxx」的那条笔记」，「查看原文」滚动到同段引用的笔记卡片（`web/src/components/ask-chat.tsx` `isolatedMarkLocation`）。
- **P2-2/P2-3 编排提速**：route/kwext/sem 三段 R294 已并行；graph→dirext 链有真实数据依赖（graph 需要召回结果、dirext 需要 graph 之后的最终上下文），强行并行会改变判据输入，不做（偏离 R295 §11 的论证：该项预估收益主要来自尚未并行的 execcls）。本轮落地 **execcls 预热**：生成原始答案一出厂即启动判别器，与 conaud（另一次 LLM 调用）并行；finalize 时答案文本未变才复用，变了重判（fail-closed，不拿旧文本判定套新文本）。判据、处置、缓存口径全部不变。
- **性能目标改口**：不再承诺 total ≤1.5s（R295 论证：不动 gen 不可达）；承诺改为 **SSE 首 delta ≤1.5s**。修复前后 total 中位与首 delta 实测对比在生产复测阶段给出。
- **P2-4**：待办/想法正文里的金额不进确定性底账（底账只认 expense/income/transfer 类目，原有口径不变）；确定性聚合答案新增提示「另有 N 条非记账笔记提到了金额，未计入以上合计」，让「没记账」与「没花钱」可区分。
- **P2-5**：verbatim 还原行长门槛 4→2（三字短行进不了候选面 = CRLF 混排永远还原不了）+ 空白行两侧对齐视为命中（连续空行不再断开连续段）。还原只在折叠相等时用原文切片替换，不引入资料外内容；危判/降级内容复活防线不变。`r295-verbatim-eval.ts`：18/20 → 20/20。
- **P3-1**：问答列表滚动改为只滚内部容器（scrollIntoView 会连带滚页面把输入框挤出可视区）+ 列表高度 55vh→45dvh（移动端地址栏/键盘下 vh 大于可视高度）。
- **P3-2**：SW/PWA 设置卡收进「高级」折叠区，默认收起（开启过离线缓存的用户默认展开）。
- **P3-3**：见 §3 财务名词路由。
