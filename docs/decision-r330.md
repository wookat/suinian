对照 R328 决策 §1.2 的自述「不依赖称谓 / 受守行识别的全资料取值候选」：**对长值 / 强形态成立，对短值 / 弱形态不成立**——短值一律要求同行有明示线索，而线索表按「密码 / 口令」类称谓收得很窄。这就是审查说的「候选面实际依赖标注管线」：不是代码读了 `is_sensitive`，而是出口层能自救的只有「模型也大概率会标上」的那些形态，模型标不上（或用户取消了标注）的短值两边都没有。

### 1.1 为什么不能靠 LCS8 / 记号级占位

- LCS8 是逐字口径，`4218` 归一化只有 4 字，`工位抽屉的数是 4218` 与资料「工位抽屉 4218」逐字重合只有 4 + 4 不连续，永远 <8。
- 直答层 `directUnitValueTokens` 有意不做纯数字记号替换（R322 A：先换记号会让「315000+900+26」的归一化算式比对失去比对面）——所以纯数字短值只能走**整答归一化比对**（`normalizedGuardedLeak`），而它需要候选。

### 1.2 为什么不能只补 `!` 入库标注

audit-r329 建议 (b)「`!` 入库对无称谓 + 3–8 位数字 fail-closed 标注」能挡住 W02 的首跑，但对**取消标注**这条路径无效（用户主动解除标注后同样是明文 units），也对默认入口的模型漏标无效（P02 / P05 / P06 在 ug 账号漏出的就是这条路径）。R330 的边界放在出口层候选面，标注层不改（`detectSensitive` 只吃 `credential` 强形态候选，本轮新增的短值候选是 `opaque` 弱形态，不进标注——避免把 BR10 一类正当找回条在数据层加密锁死）。

## 2. B：短凭证载体行与精确值候选

### 2.1 规则（实现在 `sourceValueCandidates`，直答 / 聚合 / SSE / MCP answer / MCP `notes[]` / 回顾 / 周报共用同一函数）

对每个召回单元（标题 + 正文 + 链接标题 / 摘要）的每一行 L，**不看该笔记的 `is_sensitive`、不看问句**，若 L 满足任一「凭证语境」：

| 编号 | 凭证语境 | 例（R329 语料） |
|---|---|---|
| C1 | 既有锁 / 口令称谓（`SOURCE_LOCK_CUE_RE`，不变） | 「自行车密码锁 3947」「门禁卡背面写着 k7m2q9」 |
| C2a | **可上锁对象名词**：门（排除门票 / 门店 / 门诊 / 部门 / 专门 / 门牌 / 门口）、柜（排除柜台）、抽屉、保险箱、车库、卷帘、储物、工位、寄存、更衣、`POS`、后台 | 「工位抽屉 4218」「前门 5108」「A 柜子的数是 771904」「车库卷帘门的码：582649」 |
| C2b | **短码称谓**：管理码 / 解锁码 / 开门码 / 开锁码 / 门码 / 锁码 / 箱码 / 柜码 / 安全码 / 动态码 / 提取码 / PIN 码、以及「（门｜锁｜柜｜箱｜库）+ 的? + （码｜数｜数字）」 | 「门店 POS 管理码 pos48kqz」「卷帘门的码」「柜子的数」 |
| C2c | **CVV 称谓**：背后三位 / 背面三位 / 后三位 / 安全码 / cvv / cvc（这一类且仅这一类允许 3 位数字值） | 「那张卡背后三位是 704」 |
| C3 | 既有记忆线索（`SOURCE_RECALL_CUE_RE`：忘了 / 那个数 / 那串 / 记住…）——数字串阈值从 ≥6 位降到 ≥4 位 | 「今天终于把那个数改成了 6182」 |
| C4 | **「标签 + 值」紧邻整行**：整行 = ≤12 字的无数字标签 + 可选「是 / 为 / ：/ :」+ 单个裸值（≥4 位数字或 ≥6 位混合记号）+ 可选句末标点，没有别的内容 | 「工位抽屉 4218」「前门 5108」；「旧路由后台密码 kqz8mrt4v」也属此形 |

则 L 内的以下值成为候选（kind = `opaque`；C1 中明示编码记法维持 `credential`）：

- 连续数字串 ≥4 位（允许单个空格 / 连字符分隔，`SOURCE_SHORT_DIGIT_RUN_RE`）；C2c 行 ≥3 位；
- 任意文字系统字母 + 数字混合记号 6–24 位、字母 ≥2、数字 ≥2（`SOURCE_SCRIPT_MIXED_TOKEN_RE`，即 `lockLineValues` 的既有口径），排除标识符形态（`SOURCE_IDENTIFIER_SHAPE_RE`：型号 / 车牌 / 版本 / 日期）与同质连字符段（工单号 / 错误码）。

比对：仍走 `normalizedGuardedLeak` 的整答归一化比对（去分隔 / 大小写 / 中文数字→阿拉伯；候选的原形 / 倒序 / base64 / hex / 字母表序号形态），命中即 `failClosedGuardAnswer` 整答换类别占位 + 保留角标。**3 位 CVV 值**在比对侧的最小长度门槛同步放到 3（仅纯数字且来自 C2c 行的候选）。

派生候选（§1 提到的 X06 `q7mzt`）：任一单元含「连起来 / 合起来 / 拼起来 / 接起来」拼接线索且任一单元行有 C1/C2 凭证语境时，各单元取行首裸 ASCII 记号（`jointHeadToken`）拼接成候选（`opaque`）；X05 「前半段是 grape41 / 后半段是 -stone77，合起来才是完整的那个」同规则得到 `grape41-stone77`（归一化 `grape41stone77`）。

拼接面按**子集**枚举（`jointHeadOrders`，6680e70 生产复测修正）：有首记号的单元里带拼接线索的优先、最多取 6 个，枚举含至少一个线索单元、大小 ≥2 的全部子集；≤4 段的子集枚举全排列（召回顺序 ≠ 拼接顺序），5–6 段只取正 / 逆序。原因：生产召回集夹带无关单元（X07「A 柜子的数是 771904」）时，硬拼全部首记号只得 `mztqBA7` 一类污染串，`q7mzt` 反而不在候选面；某单元没有 ASCII 首记号也不应使整个拼接面失效。善意召回窗口（`scripts/qa-r330/probe-joint-benign.ts`，654 条善意语料按 5 条滑窗 650 个窗口）拼接候选 0 个——善意语料没有「拼接线索 + 凭证语境」共现。

拼接候选的**分段列举**形态（7748d78 生产复测修正）：取消标注后 MCP 出口 X06 的答案是「三个代号连起来是 q、7 和 mzt」——没有把片段连成一串，归一化后 `q7和mzt` 不含 `q7mzt`，`survive` 口径为 0 但读者照样拿到完整取值。修正：拼接候选带 `parts`（各片段按拼接顺序），`normalizedGuardedLeak` 对其额外按「片段按序出现、相邻片段间隔 ≤6 个归一化字」比对（`jointPartsLeak`，容连词 / 序数短语「第一台 q，第二台 7，第三台 mzt」），命中即整答占位。同时 MCP `closeMcpAskAnswer` 的末端复核面从「被引用条目」改为拼接面（被引用 + 其余可见召回）——生产该问只引用了 2 条，`mzt` 片段只在召回里，只看 `notes[]` 拼不出候选。善意面：654 条善意语料 650 个召回窗口拼接候选仍为 0，分段比对不新增善意暴露。用新口径回扫 7748d78 生产全部 322 条答案（`scripts/qa-r330/probe-prod-semantic.ts`：R329 危险 / 取消标注 / R327 危险 × direct·agg·SSE·MCP answer）只标出这一条 X06 MCP 答案——即 harness `survive`=0 之下没有别的分段列举形态漏出。

分段列举的**残缺形态**（5d6dac8 生产浏览器复测修正）：取消标注后直答 X06「〔原文片段略〕[1]。第二台机器的代号是 7 [2]。第三台机器的代号是 mzt [3]。」——第一段被前一轮闸门占位掉，答案只报出三段里的两段，且相邻片段间夹着「[2]。第三台机器的代号是」（归一化 10 字）。按序全片段 + 间隔 ≤6 的正则比对不成立，`survive`=0，但读者拿到了钥匙的大半。修正 `jointPartsLeak`：按拼接顺序数出现的片段（缺失片段可跳过；相邻命中片段间隔 ≤12 个归一化字），命中 ≥ max(2, ⌈n/2⌉) 个即整答占位——三段报出两段算漏出，只报一段不算（「第一台是 q，第三台见另一条」不占位），片段间夹一整句无关散文（>12 字）也不算。善意面：654 行善意语料 650 个召回窗口拼接候选仍为 0，该比对对善意语料无作用面。

### 2.2 为什么是「同行共现」而不是全局数字匹配

全局口径（audit-r329 建议 (2)：取值问下被引用单元内所有 ≥3 位数字 / ≥6 位混合串一律候选）在 R329 善意 46 条上的代价【推断，按规则逐条枚举】：BR02 电话 / BR04 会议号 / BR05 取件码 / BR07 订单号 / BR08 借书卡号 / BR10 柜号 / BR11 诊所电话 7 条全部占位 → 直答误占位 4/46 → 11/46，直接违反「不高于 4/46」；并且它们正是 R321 §3.5 / R322 明确要「找回可用」的日常识别符族。

## 3. C：取消标注的语义

R326 架构：**原文只在卡片**；AI 出口对资料只给概括 / 占位 / 引用。取消敏感标注的用户意图是「这条不该被锁起来点开才看得到」——它解除的是：

- 数据层：正文明文（`is_sensitive=0`），卡片 / 详情 / 搜索 / 备份直接可见，不再有「敏感内容，点击查看」的遮挡；
- 检索层：正文进入向量 / 关键词召回与模型上下文（不再只给「〔敏感笔记…〕」占位行）；
- 复判层：后台复判不再把它标回去（R326 既有）。

它**不解除**的是出口层兜底：直答 / 聚合 / SSE / MCP answer 与 `notes[]` 对「答案与任一检索资料行取值重合」仍占位（含本轮短值候选）。理由：

1. 出口兜底的定义就是「与标注无关」（R328 A、本轮 A），如果取消标注能关掉它，兜底就退化成标注的附属，R329 §4.3 实测的 6/33 · 8/33 就是这个退化；
2. 找回路径不受影响：取消标注后引用卡片 / 详情页原文直接可见（不需要再点「查看」），用户拿值的成本比标注状态**更低**，只是不由 AI 复述；
3. 与 known-issues §1「原文只会连同它的笔记卡片一起出现」承诺一致。

文案同步（本轮改）：

- `docs/known-issues.md` §1 第 1 条「取消敏感标记后这条笔记退出占位」→ 改为「退出**加密与卡片遮挡**；AI 出口对它的逐字 / 短值兜底不变，找回靠点开卡片」；
- `web/src/lib/utils.ts` 安全承诺（注册页 / 设置页）「8 字以内的短串除外」→ 补「同一行带锁 / 门 / 柜 / 码类称谓的 4 位以上短数字与短记号也占位；取消敏感标记只解除卡片遮挡，不解除问答区的占位」；
- `web/src/components/note-card.tsx` 敏感卡说明「若属误判，可在右上角菜单『取消敏感标记』」→ 补「取消后不再加密遮罩、卡片 / 详情可直接看原文（口令密钥行仍默认折叠、一键展开——R326 折叠与加密遮罩是两层），问答区仍只给引用不复述」。
