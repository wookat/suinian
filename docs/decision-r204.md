# R204 修改轮决策记录（落实 audit-r203）

对应审查报告：`docs/audit-r203.md`（R203 终定 GO，P0/P1/P2 全零；5 个 P3 + 1 个待定项 + Android Tab 疑似伪象复核）。统一管道原则：全部收口在既有管道内，不新增平行逻辑。

## 1. P3-1 英文财务笔记分拣弱 → 修复（prompt 判例，既定管道）

R203 生产实测：`coffee beans 128 CNY` → collect 且 `amount=null`，后续问答查不到。属 LLM 对英文/中英混合记账的语言偏置，与 R202 §4「用量换算」同类：分拣语义规则缺显式判例。

修复（`triage.ts` prompt）：在 AA 判例前加显式规则「英文/中英混合记账同样按上述规则分拣：句中出现货币词（CNY/RMB/USD/$/¥/元/块）＋金额的购买/支付/收款叙述就是记账」+ 三个判例（coffee beans 128 CNY→expense/128/CNY、$45 键盘→expense/45/USD、freelance 3000 CNY received→income/3000/CNY）。prompt 判例是该管道既定修复手段（R195/R197/R202 同路径）；不加输出侧语言检测后校验——无确定性识别特征，会误伤真实英文收藏类笔记。eval 集补 3 例锁定。

## 2. P3-2 线索聚类精确率 → 不改（论证，留专项）

R203 实测：阳台种菜簇精确 5/7（吸入 2 条弱相关）、JR Pass 被拆入混合簇（召回 4/5）；两大主题簇间无交叉污染。audit-r203 §9 本身即建议「作为 decision-r202 §6 预留的召回/聚类专项的一部分统一设计（按 SOP-02 先出样本与验证方式）」。

论证：聚类精确率与召回同义改写（R201 P2-1、R203 仍现 2 例同类）同属 embedding 语义空间质量问题，不存在确定性收口点——逐簇打补丁（调阈值/加规则）正是「修一类又现一类」模式，且调高聚类阈值提精确率必然伤召回率，没有样本集与验证方式前的任何阈值改动都是拍脑袋。维持现状，留待专项按 SOP-02 出样本论证（样本：≥5 组人工标注主题系列 + 干扰笔记；验证：precision/recall 双指标对比现状）。本轮不改。

## 3. P3-3 「想尝试一周不喝奶茶挑战」→ todo → 修复（prompt 判例）

R203 实测 50 条唯一错例（98% 中的 1 例，审查自评「可争议」）。评估：意愿/心愿式表达（想尝试/想试试/有机会想…）没有明确执行安排或时间承诺，归 idea 更符合「待办=需要去做的事」心智，且误标 todo 会污染「悬而未决」清单（R107 P2-3 同向）。

修复（`triage.ts` prompt）：在完成式日志判例后加「意愿/心愿式表达是想法不是待办」规则 + 两个判例（想尝试一周不喝奶茶挑战→idea、有机会想去趟敦煌→idea）。eval 集补 1 例锁定。注意边界：已有明确安排的「想法+安排」（如「想去敦煌，十一订票」）仍按动作归 todo，判例措辞已限定「没有明确的执行动作安排或时间承诺时」。

## 4. P3-4 售后电话过度敏感（待定项）→ 维持加密口径 + 遮罩态低成本改进

老板尚未拍板敏感边界，默认维持现状：整条加密是 R118 决策延续（fail-closed，隐私安全方向），本轮**不改变加密口径本身**。

落实的低成本改进（Web + Android 双端）：敏感遮罩态原本只有「敏感内容，点击查看」，用户不知道**为什么**被加密、也不知道误判时如何解除。遮罩卡片补一行说明：「检测到密码/凭据类信息，已自动加密保护，不进入问答与搜索；若属误判，可在（右上角）菜单取消敏感标记」。一键解锁路径核验：Web 点击遮罩即临时显示明文（无需输密码，owner 已认证）、卡片菜单「取消敏感标记」永久解除；Android 同构。路径本身顺畅，缺的只是「为什么」的说明，已补。

## 5. P3-5 Android 注册按钮压缩布局下静默无响应 → 修复（通用失败反馈）

R203 受控复现（`wm size 400x860`）：点击「注册并开始使用」无任何反馈。分析：引导页错误文案渲染在按钮上方的滚动列内，布局压缩/键盘弹起时可能整体不在视口内，错误实际已设置但用户看不见 → 表现为「静默无响应」。

修复（`OnboardingScreen.kt`）：错误设置统一走 `fail()`（单调计数 `errorTick` + `LaunchedEffect`），在页内错误文案之外**兼发一条 Toast**——Toast 由系统绘制在窗口顶层，不受布局压缩/滚动位置影响，同一文案重复触发也能再次提示。不限于小屏场景（audit-r203 §9 建议原文），网络失败/服务端错误同样受益。按钮已有 `enabled=!busy` 禁用态，无需重复加。
