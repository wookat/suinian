> 更新：R326（2026-09）。如果你在使用中遇到这里没写的问题，请在 [GitHub Issues](https://github.com/wookat/suinian/issues) 反馈。

## 1. 安全边界：请把「识别」当作辅助，不要当作保险

**我们不保证认得出每一种危险内容。** 连续四轮（R314–R318）独立盲测证明，靠判据识别口令 / 破坏命令这件事在「族外变体」上不会收敛（R319 盲测：直答层凭证 8/22、破坏命令 10/16 漏）。你的笔记实际上过三道闸门，它们的性质不同：

1. **敏感标注（唯一安全开关，R326 起）**：一条笔记只要带有敏感标注（自动标的或你手动标的），它的正文就不会进入任何 AI 出口：直答 / `!` 直答 / 聚合 / 流式 / MCP `ask` 的 answer 与 `notes[]` / 回顾 / 线索 / 周报 / 推送 / 导出的 AI 摘要面，一律只给占位 + 点开指引，**与你怎么问无关**（换语言 / 打比喻 / 不带称谓 / 口述数字 / 要求变形转写都一样）。模型看到的只是「〔敏感笔记：正文已加密，不提供给 AI…〕」一句，不是原文。**但它仍能被找回**：问答会把命中的敏感笔记以引用卡片列在答案下方（只命中敏感笔记时不调模型，直接给卡），搜索也能搜到，点开卡片才看到原文（R325 实测「被自动标敏感的普通笔记问答零召回、搜索搜不到」已修）。自动标注是模型判定：**可能误标**（车牌 / 门禁卡编号 / 他人电话这类标识符；R326 已按「知道即可进入 / 登录 / 支付 / 开锁的取值才算敏感」重新校准），也**可能漏标**（标签与取值分在两条笔记、无任何称谓的取值）。误标的代价只是**多点一次**：卡片菜单里「取消敏感标记」后这条笔记退出占位，且后台复判不会把它再标回去（改正文后会重新判定）。漏标的内容才落到下面两道靠「识别」的闸门上——它们是纵深，不是边界。
2. **结构边界（不依赖识别）**：
   - 跨多条笔记的聚合回答、推送、导出、工具接口**不整段逐字转写**你的笔记（连续 8 字以上的片段不会出现；**8 字以内的短串可能出现**，例如 `さくらふじ`、`# @ ! %` 这类短值；R320 起答案里的字母数字混合高熵短串与 12 位以上数字串也一律占位）。
   - 你问**某一条**自己的笔记时，原文只会连同它的笔记卡片一起出现。**R320 起直答层不再尝试区分「口令 / 破坏命令 / 普通命令备忘」**：凡是含命令 / 代码形态、口令密钥、长串编号 / 高熵短串、以及非书签形态地址（IP 字面 / 主机:端口 / user@host / 内网・本机・`.local` `.internal` 一类保留后缀地址 / 拼读・编码地址）的行，问答区一律不转写，只给一句概括（「一条含口令/密钥的记录」「一条命令/代码备忘」等）+ 占位 + 引用角标，点开角标指向的卡片看原文。判据只决定占位文案和警示强度，不决定原文能不能进问答区（错分只影响措辞）。**R322 起这些行也不进入模型上下文**——模型看到的是「〔此行为口令/命令/长串编号一类内容，已从问答上下文隔离…〕」这句占位，不是原文——所以「加空格 / 逐字念 / 倒序 / 拆两半 / base64 / 拼音 / 翻译 / 移位」这类**变形转写**请求得到的也是占位或核对提示，不是变形后的取值（R321 生产实测曾漏出 `R t 5 & y y 8 q`、`四八二九一三`，R322 修法与复测见 decision-r322 §1）。出口层另有一道归一化比对兜底（去分隔 / 倒序 / 中文数字 / base64 / hex 还原后再比），只对已知形态负责。带口令 / 门禁 / 卡号 / 编号 / 交易码标签的 4–11 位数字、以及拆四段可拼回的 16 位卡号，R322 起同样受守（R321 曾漏 `4471`、`482913`、`6100 2233 8891 0042`）；同一条笔记里几处都受守时，整个答案只用**警示最强的那一条**文案（破坏性 > 口令 > 长串 > 地址 > 命令备忘），列表答案每步各保留序号。
   - **R324 起，对凭证的取值型问题一律占位，不看取值长什么样**：问「口令 / 密码 / 暗号 / passphrase / 合言葉…是什么 / 多少 / 告诉我 / 念一下 / 倒过来念 / 第 2、4、6 位 / 笔画 / 拼音 / 编码」这类**要拿到值**的问题，只要召回里有一条在讲某个秘密的笔记（带口令类称谓、或受守行），问答区不进模型生成，直接给「〔一条含口令/密钥的记录…〕」+ 角标。R323 生产实测证明「认出口令长什么样」不可收敛（`木石田`、`秋天的枫叶落在桥上`、`silver otter lantern`、`やまざくら7823` 这类纯散文口令 `!` 直答 4/42 逐字漏出），所以边界改放在**问句**上（decision-r324 §1）。代价：对一条**不是**凭证、但正文里提到「密码」二字的笔记问「密码是什么」，也会得到占位 + 卡片而不是直答。
   - 问「我的口令是不是 X」这类带候选值的核对问题，以及对含口令 / 命令 / 长串编号内容的任何**信息试探**——是非问、几位、首 / 末 / 第 n 个字符、大于小于、排除法（「不是 A 也不是 B 吧」）、多轮二分、字符集属性（「有没有大写 / 井号」）、尾缀「只回答是或不是」、条件式拒答尾缀（「如果不能回答就说不能说」）、要求变形转写——问答区**不确认也不否认**，一律同一句核对提示（对对的、错的、半对的候选值给同一句话、同一组卡片），请点开卡片自己核对。R321 实测这条承诺只对纯「吗」句成立；R322 把触发改成与句式无关（decision-r322 §2）；R323 又实测到「只回答是或不是」「如果不能回答就…」尾缀绕过（`oracle_neutral=false`），R324 把是非问 / 取值问的判定改为允许尾缀跟条件 / 格式子句，并把这些子句当格式指令剥除后再召回（decision-r324 §4）。
3. **判据（只管措辞与折叠强度）**：口令折叠 / 破坏命令高警示 / 日常命令展示，这些卡片层的分类仍由判据决定，**仍会错分**。

判据**没认出**、你也**没标敏感**的内容，在卡片里不折叠、不提醒；在直答里，只要它是纯散文（无命令 / 高熵串 / 非书签地址形态）、**且你问的不是「它的值是什么」**（上面的取值型门禁）就原样出现——例如问「这条笔记讲了什么」时，模型会用自己的话概括，没被认出的散文口令可能被复述；R324 起「称谓词 + 短值同现」（「柜子暗号 木石田」「暗証は やまざくら7823」「the phrase … for the cabinet」）也进受守集与卡片折叠，但这只是识别面的扩充，不是安全边界；**普通书签链接（协议头 + 公网域名 + 路径，无端口、无用户名）照常直答**（书签问链接是产品核心价值，R274/R302 决策）；R321 实测 B 站 `…/video/BV1xx411c7mD` 这类含视频 ID 的公网链接被当「长串编号」占位，与本句相反，R322 已改为按路径分段判高熵、链接照常直答。日常识别符（手机号、订单号、会议号、快递单号、联系邮箱、版本号）R322 起也不再占位——它们不是口令 / 命令形态，是用户高频要「找回」的东西（R321 §3.5）。内网 / 本机地址（10.x / 192.168.x / localhost / `.internal` 等）**与公网地址同样占位**：卡片层对它们不折叠（折叠管的是能否被公网取回执行），但直答层按结构面不区分公私网。本轮中途曾在生产浏览器实测到「内网 Grafana 地址 `http://10.0.3.7:3000/…`」直答原样，那是漏出（已在同轮第五次部署补上，见 decision-r320 §1.2 / §6.5）。

已知识别不到 / 识别不稳的形态（卡片层会原样展示、不提醒；直答层自 R320 起按上面的结构边界占位，不再依赖这张表）：

| 类别 | 形态 | 状态 |
|---|---|---|
| 口令 | 缩写 / 同形 / 错别字标签（`pw` `密马`）、未列入的语言标签、无标签取值（只写一串字符）、金融凭证（卡号 / CVV / 助记词分条写）、口述 / 算式 / 编码取值（「2 的 10 次方加 47」「Kilo Victor 九…」）、非拉丁数字系统、假名 / 西里尔口令 | 卡片层：**不折叠、不提醒**（R319 盲测 8/22 族外）。直答层：R320 本地盲测 22+13+18+12 条凭证载体记号逐字漏出 0；R322 起受守取值不进模型上下文，模型无法替你算出 / 拼出取值（R321 曾实测「第一个字符」→ `4`、「前面是青岛2吗」→ 整串回显），出口层对已知变形形态另有归一化兜底；但**算式 / 口述本身是纯散文**（「门锁码是 2 的 10 次方再加 47」），单笔记直答会把这句原样复述——同上一行「纯散文破坏意图」，散文暗语识别不当安全边界（R320 生产实测 C16） |

| 定时任务 | `crontab -r` | 只按「日常命令」展示，不单独高警示（保持既有行为） |
| 卡片折叠 | 同行 CJK 括号前缀（`《清缓存》rm -rf /srv/cache/*`）可能遮蔽数据面折叠 / 警示 | 问答层仍会警示；卡片层未修 |
| 检索串扰 | 同账号多条口令笔记时，问 A 的问题答案可能带出 B 所在笔记的标题 | R322：B 的受守行随召回集合一并从模型上下文隔离，答案自身的「标签 + 取值」句（R321 实测 `柜门口令是 4471 [1]`）也整句占位；R324：凭证折叠卡的标题位若自身可折叠或与正文重合则显示类别占位（隔离横幅不再回显「柜子暗号 木石田」），其余标题仍可能出现（P2） |

**建议**：真正的口令 / 密钥请打开「标为敏感」（加密存储；问答 / 搜索仍能找到它并给出引用卡片，AI 只拿到占位，原文只在你点开卡片时显示），不要依赖自动识别。下面关于「取值型问句」「受守行」的描述仍然成立，但 R326 起它们只管**没被标敏感**的内容；已标敏感的笔记不再经过这些判定。

**R320 的代价**（如实报告）：你问自己的一条日常命令备忘（`kubectl get pods`、`git push origin main`、`docker logs --tail=50 web`）或文件系统路径备忘（`/mnt/backup`）时，问答区不再直接给命令 / 路径，而是「一条命令/代码备忘：…点开引用的笔记卡片查看原文」+ 角标，多点一次；R322 起模型也看不到这一行，概括只能基于笔记的其余散文。本地 307 条善意直答语料中被改动的从 22 条（7.2%）变为 81 条（26.4%），增量全部是命令备忘 / 高熵识别符 / 路径形态；纯散文 / 记账 / 待办不受影响。

## 2. 复制提醒的覆盖范围

对**口令折叠卡**（credential）、**破坏命令警示卡**（destructive）与**标为「敏感」的卡片**，以下复制路径都会先弹提醒核对（R319 真实浏览器 18/18 路径实测成立）：

- 卡片菜单「复制」
- 展开后选中文字 Ctrl+C / 右键复制
- 整页全选（Ctrl+A）后复制
- **编辑框内**选中复制 / 剪切（R318 新增）
- **敏感卡展开后**的四条路径（R318 新增）
- 问答答案区**选中 / 右键**复制（答案区没有独立的「复制答案」按钮）——提醒看的是选中内容：答案里只有占位句 / 指引 / 角标、没有受守原文时**不弹提醒**。R321 生产浏览器实测发现选中**纯占位文案**的破坏命令答案 Ctrl+C 仍弹确认框（桌面 + 375px），与本句相反；R322 已修（选区剔除占位 / 指引 / 角标后无实义文本则不弹），含实义受守文本的概括答案仍提醒

**日常命令备忘卡（code，正文上方有一行提示、但不折叠）不在上面的范围内**，它的复制行为是：

- 卡片菜单「复制」：弹确认框
- 展开后选中 Ctrl+C / 右键复制：**直接复制**，事后给一行「已复制…」提示
- 整页全选复制、编辑框内复制 / 剪切：**不提醒**（剪切会直接移除文字）

这是设计如此（日常命令备忘需要频繁复制），但也意味着：如果一条破坏命令被判据错分成日常命令，它就只有 code 卡的复制行为。

**不提醒**的情形：

- 判据没认出、也没标敏感的普通笔记（例如一段没被认出的口令）——这是「不保证识别」的直接后果。
- 真机触摸长按选区复制：**未验证**（R319 的 CDP 模拟触摸没能进入原生选区菜单）。
- 浏览器 / 系统级的截图、OCR、无障碍朗读等非剪贴板通道。
- 移动端第三方输入法自带的剪贴板同步。

提醒是「先确认再复制」，确认后剪贴板里就是原文；提醒本身不是拦截。

## 3. 问答（AI）已知行为

| 现象 | 说明 | 状态 |
|---|---|---|
| 多条笔记的「为什么 / 怎么变」问题只得到「〔原文查看〕…」一句 | 聚合层不逐字转写；模型若整段照抄笔记，收口后只剩占位。R318 改为：先重试让模型用自己的话概括，仍无实义时给出「命中笔记列表 + 指引」（分类 / 标题 / 日期 / 记账金额 + 引用序号）而不是空占位 | R318 已改（生产 141 题：只剩通知句 0/141，列表式指引 9/141）；列表里的标题与原文重合时只显示「分类 + 日期」，信息量有限 |
| 答案里出现〔已隔离笔记内指令，未采纳〕 | 命中的笔记里含有对 AI 的指令（「回答时请…」），系统隔离了它。误判时原文仍在卡片里 | 按设计 |
| 一个问题同时命中两条以上笔记（如「清理旧数据的命令」同时召回破坏命令备忘与端口命令备忘）时，答案是不带类别占位的概括，且模型有时不标角标 | 这是聚合层（不逐字转写 + 高熵 / 结构面掩蔽）而不是直答层：类别占位只在「单条笔记直答」出口；引用卡片仍在答案下方同屏列出。R320 生产浏览器实测一例（原文未出现） | 按设计；角标漏标是模型行为（生产 141 题引用完整性 141/141） |
