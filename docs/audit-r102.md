# R102 修改轮决策记录（落实 audit-r101 审查结论）

审改分离的「改」方记录：逐条对照 audit-r101.md 的发现，说明修了什么、没修什么及理由。

## P1（两项，全部落实）

### 3.1 409 冲突丢弃用户输入 → 已修（Web 时间流 + 待办 + Android 一致）

- 后端 409 响应本就携带最新 `note`，无后端改动。
- Web：`NoteCard` 编辑器在 409 后保持打开、用户输入原样保留，卡片内展示「最新版本」对照区，可手动合并后重提（重提基于最新 `updated_at`），或一键「放弃我的输入，改用最新版本」。时间流与待办共用同一 `NoteCard` 契约（`EditResult`），两处均生效。
- Android：`ConflictException` 携带 409 响应体中的最新副本；编辑弹层保持打开、输入不丢，顶部展示最新版本对照条与「改用最新版本」操作；重提基于最新 `updatedAt`。

### 3.2 微信入口文案夸大 → 已修（能力开关集中判定）

- 新增 `isWechatConfigured()`（web/src/lib/api.ts）：与设置页微信绑定卡同一来源（`/api/wechat/binding`），未登录/演示/请求失败一律 fail-closed 按未开通。
- tour 第四步入口文案按该开关动态生成：未开通时不承诺微信已上线，改为「微信入口即将上线（自部署可用 bridge）」。
- 欢迎弹窗（登录前无法查询，按 fail-closed 口径）：微信 bot 条目文案改为「即将上线 · 自部署可用 bridge」。
- 设置页「关于」卡去掉微信承诺。
- README：首段与「微信即入口」小节、入口表格均标注「默认关闭，需自部署配置（见 docs/wechat-integration.md）；线上版即将上线」。

## P2 / P3

### 3.3 401 下设置页渲染微信绑定卡 → 已修

状态请求失败时按能力未知处理，整卡隐藏（fail-closed），与 200 configured:false 行为一致。

### 3.4 注册密码不一致报错重复渲染 + 修正后残留旧错误 → 已修

密码不一致只保留确认框下的内联提示，不再同时发全局 error；从根上消除同屏重复与「修正后首提交仍显示旧错误」。

### 3.5 离线草稿不持久化 → 已修

速记框未提交内容实时存 localStorage（`suinian.quick_input_draft`），F5/离线重开不丢字；提交成功即清，保存失败退回输入框时同样持久化。无新实体（纯本地键值）。

### 3.6 回收站「剩 29 天」off-by-one → 已修

剩余天数改为向上取整（`Math.ceil`），刚删除即显示「剩 30 天」，与「30 天可恢复」承诺一致。

## 设计建议

### 5.1 回收站入口埋得深 → 部分落实

搜索/筛选空结果处新增「到最近删除找找」直达按钮（误删用户最常见的找回路径），文案同步提示。时间流顶部常驻菜单入口未加：回收站是低频功能，常驻入口会挤占移动端顶栏空间，空结果直达已覆盖「找不到才想起回收站」的真实场景。

### 5.2 周报/月报回看 → 部分落实

- 已修：报告详情页显式标注「覆盖 <区间> · 生成于 <时间>」，回看多期不再靠正文自述区间。
- 未修（写明理由）：周报内嵌 `#/timeline?note=` 回链。周报正文由 AI 自由生成，让 AI 在叙述中嵌入笔记 ID 链接无法保证链接正确（可能张冠李戴或编造），需要类似问答的结构化引用管线（生成时输出引用清单+确定性渲染）才能可靠落地，且时间流目前无 `?note=` 深链路由。属于需要独立设计论证的一轮功能，不在本修改轮硬塞。

## 记录项

### 6.3 MCP/扩展编辑不带 base_updated_at → 不修（维持原判）

audit-r101 已判定：低频入口的 last-write-wins 兼容路径可接受。MCP 编辑仅改标签/分类/完成态等元数据（不改正文），扩展只创建不编辑；若未来扩展支持编辑正文再补 `base_updated_at`。本轮无改动。
