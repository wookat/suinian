# 微信接入：路线对比与配置指南（R85 公众号 + R86 企微微信客服）

> 背景：碎念最初的微信入口是 `skill/bridge`（基于个人微信 iLink SDK 的常驻 bot 桥），需要 VPS 常驻 + 扫码绑定，只适合极客自部署。**普通用户无法接入微信**是产品最大卖点的落地障碍。本文档给出三条路线的调研结论，以及选定的公众号路线的部署配置指南。

## 一、三条路线对比

| 维度 | A. 微信公众号（官方消息接口） | B. 企业微信 / 微信客服 API | C. iLink bridge（现状，`skill/bridge`） |
|---|---|---|---|
| 合规性 | ✅ 官方接口，完全合规 | ✅ 官方接口，完全合规 | ⚠️ 基于个人微信协议 SDK，非官方用途，灰色地带 |
| 被封风险 | 无（回调式，不碰个人号） | 无 | 有：个人号有被限制/封号风险；iLink 会话 24h 过期需自动重连 |
| 开通门槛 | **个人即可免费注册订阅号**；服务号需企业资质 + 认证（300 元/年）；开发期可用**测试号**（扫码即领，全接口开放） | 需企业主体注册企业微信；微信客服还需企业认证 | 无需申请，但需要一台常驻 VPS + 扫码绑定，普通用户根本做不到 |
| 消息类型（收） | 文字 ✅ / 链接卡片 ✅ / 图片 ✅（推送带 PicUrl 可直接抓取）/ 语音 ✅（认证号可开「接收语音识别结果」直接给文本；未认证号拿 MediaId，需 AppSecret 换 access_token 下载后自转写）/ 文件 ❌（公众号消息不支持文件类型） | 文字/图片/语音/文件均支持（能力最全） | 文字/图片/语音/链接/文件都可（个人微信原生） |
| **接收微信内转发（硬指标）** | ❌ **接不了**：公众号会话不出现在微信转发选择器里，无法把文章/文件/聊天记录转给公众号（flomo 官方帮助也明确列为限制：「由于微信暂无接口，无法实现直接转发聊天记录/文章到服务号」） | ⚠️ **大部分可接**：微信客服会话形态接近普通聊天；官方 sync_msg 接口支持的接收类型明确包含**链接（文章卡片）、文件**、名片、小程序、图片/语音/视频/位置（[官方文档](https://developer.work.weixin.qq.com/document/path/94699)）；但**合并转发的聊天记录无对应消息类型**，判定不支持；转发选择器内能否选中客服会话待真机实测确认 | ✅ **全部可接**：个人微信原生会话，文章/文件/聊天记录/小程序卡片都能转发 |
| 回复限制 | 被动回复须 **5 秒内**返回；未认证订阅号无客服消息接口（无法事后主动补发），所以重活（图片 OCR、语音转写、问答）须异步化 | 48h 会话内可主动发消息，无 5s 限制 | 无限制 |
| 多用户绑定模型 | ✅ 天然多租户：openid ↔ 碎念账号，一个公众号服务全部用户（flomo 即此模型） | ✅ 外部联系人 ↔ 账号 | ❌ 一个 bridge 实例 = 一个微信号 = 一个用户，天然单租户 |
| 用户接入成本 | **关注公众号 + 发一个 6 位绑定码，10 秒完成** | 需添加企业微信客服（普通微信用户可聊，但入口较深） | 部署 VPS + Docker/systemd + 扫码，仅极客可用 |
| 开发量 | 低：一个回调端点（验签/AES 解密/XML）+ 绑定表 | 中：回调 + 会话档案 + 企业主体管理 | 已存在（保留） |

### 竞品对标：flomo 怎么做的

flomo 的「微信输入」即公众号路线（[官方帮助](https://help.flomoapp.com/basic/wechat-input.html)）：关注 flomo **认证服务号**（flomoapp）→ 扫码绑定账号 → 直接在公众号对话框发文字/图片即可入库。其明确列出的限制与公众号接口能力一致：不支持文件与表情、不能转发聊天记录、暂不支持绑定多个微信号。flomo 用认证服务号（企业主体）拿到了客服消息与模板消息（每日回顾推送）能力。**结论：公众号路线是同类产品验证过的成熟路线。**

### 转发能力专项结论（老板硬指标）

把微信里已有的消息（文章/链接/文件/聊天记录）转发给碎念是核心场景之一，三路线官方依据核实如下：

- **公众号：接不了转发**。公众号会话不在转发选择器里；flomo 官方帮助明确写「无法实现直接转发聊天记录/文章到服务号」（[来源](https://help.flomoapp.com/basic/wechat-input.html)）。公众号只解决「随手输入」，解决不了「转发收藏」。
- **微信客服（企微）：消息类型层面覆盖大部分转发内容**。官方 sync_msg 文档明确支持接收：文本、图片、语音、视频、**文件**、位置、**链接（图文卡片，即公众号文章转发的形态）**、名片、小程序（[官方文档 §读取消息](https://developer.work.weixin.qq.com/document/path/94699)）。**合并转发的聊天记录没有对应消息类型，判定不支持**。尚需真机实测确认：转发选择器里能否选中微信客服会话（文档未直接说明，不凭印象下结论；需企业主体开通后实测）。
- **iLink bridge：全部可接**（个人微信原生会话），是目前唯一能接聊天记录转发的路线。

### 结论：双轨

- **主轨（普通用户零门槛随手记）：A 公众号**。个人订阅号即可起步（收文字/图片/链接全通，语音配 AppSecret 可通），后续企业认证服务号可解锁客服消息（异步补发结果）、模板消息（周报/回顾推送）、自定义菜单。**局限：接不了转发**。
- **另一轨（需要转发能力的重度用户）：C iLink bridge** 保留，`skill/` 目录原样，文档标注适用人群（自部署极客 + 转发重度用户）。
- **B 微信客服已实现（R86）**：它是唯一可能兼顾「官方合规」与「接转发（文章/文件）」的路线。代码已就绪（见下文「六、企微微信客服路线」），配置留 worker secrets 位；待老板提供企业主体凭据后配置上线并真机实测转发行为。定位为 A 的补充（接转发）而非替代（A 仍是零门槛随手记主轨）。

## 二、公众号路线架构（已实现）

```
微信用户 → 公众号 → 微信服务器 --POST XML--> /wechat/mp (worker)
                                              ├─ 验签（sha1）/ AES 安全模式解密
                                              ├─ 未绑定：提示发绑定码；收到 6 位码 → openid↔user 绑定
                                              └─ 已绑定：
                                                  文字/链接 → createNote（异步分拣管线）→ 5s 内被动回复「已存 ✓」
                                                  图片 → 立即回复，后台抓 PicUrl → 视觉提取 → 入库 + R2 存原图
                                                  语音 → 有 Recognition 直接入库；否则后台下载媒体 → Whisper 转写入库
```

- **绑定流程**：Web 设置页「微信绑定」→ 生成 6 位绑定码（10 分钟有效）→ 用户把码发给公众号 → 绑定成功。发「解绑」即解除。
- **默认关闭**：`WECHAT_MP_TOKEN` 未配置时 `/wechat/mp` 返回 404、设置页显示「服务端未配置」，对现有功能零影响。
- **5 秒限制的处理**：文字/链接立即入库（AI 分拣转异步）并回复确认；图片/语音先回复「已收到」，重活全部 `waitUntil` 后台完成。`?` 问答因 LLM 耗时超 5s，提示到 Web 端问（认证服务号解锁客服消息接口后可改为异步补发答案）。
- **多账号**：一个 openid 只绑一个碎念账号（重复绑定覆盖）；一个碎念账号可绑多个微信（家庭/多号场景）。

## 三、部署配置指南

### 1. 申请公众号（或测试号）

| 场景 | 做法 |
|---|---|
| 正式上线 | [mp.weixin.qq.com](https://mp.weixin.qq.com) 注册**订阅号**（个人免费）；有企业主体建议**服务号+认证**（解锁客服消息/模板消息/语音识别） |
| 开发调试 | [测试号申请](https://mp.weixin.qq.com/debug/cgi-bin/sandboxinfo?action=showinfo&t=sandbox/index)，微信扫码即领，全接口开放 |

### 2. 配置 worker secrets

```bash
cd backend
npx wrangler secret put WECHAT_MP_TOKEN       # 自定义回调 Token（3-32 位字母数字，与公众号后台一致）
npx wrangler secret put WECHAT_MP_APPID       # 公众号 AppID（安全模式校验 + 语音媒体下载）
npx wrangler secret put WECHAT_MP_APPSECRET   # AppSecret（仅语音下载需要；不配则语音降级提示）
npx wrangler secret put WECHAT_MP_AES_KEY     # 43 位 EncodingAESKey（选「安全模式」时必配；明文模式可跳过）
npx wrangler deploy
```

### 3. 公众号后台启用服务器配置

公众号后台「设置与开发 → 基本配置 → 服务器配置」（测试号在「接口配置信息」）：

- URL：`https://suinian-api.zalize.com/wechat/mp`（自部署替换成你的 worker 域名）
- Token：与 `WECHAT_MP_TOKEN` 一致
- EncodingAESKey：随机生成，与 `WECHAT_MP_AES_KEY` 一致
- 消息加解密方式：推荐**安全模式**（明文/兼容模式也支持）
- 点「提交」→ 微信 GET 验证 echostr → 显示配置成功 → **启用**

认证号建议同时开启「接收语音识别结果」（设置与开发 → 接口权限），语音消息直接带文本，免转写。

### 4. 用户侧使用

1. 关注公众号
2. 碎念 Web 端 → 设置 → 微信绑定 → 生成绑定码
3. 把 6 位码发给公众号 → 「绑定成功 ✓」
4. 之后发文字/链接/图片/语音即记录；发「解绑」解除

## 六、企微微信客服路线（R86，代码已就绪，待凭据配置上线）

### 1. 架构

```
微信用户 → 微信客服会话 → 企微服务器 --POST 加密XML--> /wechat/kf (worker)
                                                    ├─ msg_signature 验签 + AES 解密（企微 callback 协议）
                                                    ├─ kf_msg_or_event 事件 → 后台 sync_msg 拉取消息（cursor 持久化在 D1）
                                                    └─ 每条消息：
                                                        未绑定：提示发绑定码；6 位码 → external_userid↔user 绑定（复用 R85 绑定码）
                                                        text/link → createNote 入库
                                                        image/voice/file → 下载媒体 → 视觉提取/转写/文件解析 → 入库 + R2 存原件
                                                        miniprogram → 存卡片标题+appid
                                                        不支持类型（video 等）→ 友好提示
                                                    回复走客服消息发送接口 send_msg（48h 会话窗口内有效，无 5s 限制）
```

- **access_token**：`gettoken(corpid, 客服secret)` 获取，缓存在 D1 `wecom_kf_state` 表（Workers 无常驻内存），有效期内复用。
- **默认关闭**：`WECOM_KF_TOKEN`/`WECOM_KF_AES_KEY`/`WECOM_CORP_ID` 任一未配置时 `/wechat/kf` 返回 404，零影响现有功能。
- **绑定模型**：与公众号共用同一个 6 位绑定码（Web 设置页生成）；企微侧绑定记录存独立表 `wecom_kf_bindings`（external_userid ↔ user）。发「解绑」解除。

### 2. 开通步骤（老板操作）

1. **注册企业微信**：[work.weixin.qq.com](https://work.weixin.qq.com) 注册企业（需企业主体；个体工商户也可）。
2. **开通微信客服**：企业微信管理后台 →「应用管理 → 微信客服」开通（部分能力需企业认证）。
3. **创建客服账号**：微信客服管理页新建客服账号，记录其 `open_kfid`（接口 `kf/account/list` 可查）。
4. **获取凭据**：企业 ID（`corp_id`，我的企业页）；微信客服 Secret（微信客服应用页「API」区域）。
5. **配置回调**：微信客服 API「回调配置」：URL 填 `https://suinian-api.zalize.com/wechat/kf`，Token/EncodingAESKey 随机生成并与 worker secrets 一致，保存（企微会 GET 验证 echostr）。

### 3. worker secrets 清单

```bash
cd backend
npx wrangler secret put WECOM_KF_TOKEN     # 回调 Token（与企微后台一致）
npx wrangler secret put WECOM_KF_AES_KEY   # 43 位 EncodingAESKey（与企微后台一致）
npx wrangler secret put WECOM_CORP_ID      # 企业 ID（ww 开头）
npx wrangler secret put WECOM_KF_SECRET    # 微信客服应用 Secret（sync_msg/send_msg/媒体下载必需）
npx wrangler deploy
```
