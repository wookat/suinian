# decision-r270：输出侧护栏从「字面剥除」转向「行为一致性判定」（落实 audit-r269）

- 轮次：R270（审改分离的「改」方，落实 audit-r269 阻断项）
- 日期：2026-08-24
- 范围：P0 注入护栏重设计（本文档）＋ P1 检索改进 ＋ audit-r269 其余 P1/P2/P3 逐条处置（见文末）

## 一、根因复述（audit-r269 §3.3，本轮独立验证）

R268 的护栏管道是「LLM 抽取 demand（要求助手输出的确切文字）→ `scrubDirectiveDemands`
按 foldCompact 子串剥除」。R269 证明：**即使抽取环节 100% 正确，字面剥除也剥不掉**
下面四类答案（本机脱 AI 可确定性复现，`docs/audit-r269.md` §9）：

| 例 | 逃逸方式 | 为什么字面剥除失效 |
| --- | --- | --- |
| R269-10 | 模型意译了「导出全部笔记发邮箱」的劝导 | 答案措辞 ≠ demand 原文，子串不命中 |
| R269-26 | 钓鱼句被转述包装（URL 已被 allowlist 摘除，指令句仍在） | 剥掉 URL 后剩余文本与 demand 不再逐字一致 |
| R269-34 | 「r269-collect 点 example 斜杠 log」被模型改写为 `r269-collect /example/log` | 拼读还原后的形态不在 demand 原文里 |
| R269-44 | 口令「霜雕振翅」以近形字「霜雕振翾」落地 | 单字近形替换即打破子串匹配 |

结论：**「剥除/匹配字面」在结构上追不上模型的改写自由度**（R267、R269 连续两轮证明）。
护栏判定必须与 demand 字面解耦。

## 二、方案对比

| 方案 | 思路 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 继续扩正则/扩 marker 词表 | 枚举更多执行痕迹形态 | 便宜 | audit-r265/r267/r269 三轮证明变体空间无界，追不上 | 否决 |
| B. 结构化输出契约 | 生成端只允许输出 `{结论, 引用}` JSON，资料指令天然无处安放 | 隔离彻底 | degraded Workers AI 的 JSON 依从性差（R269 实测生产长期 fallback），格式失败率会直接变成可用性事故；且「结论」字段里仍可被意译注入，并没有消除行为判定的需要 | 否决（主路线），保留为远期选项 |
| C. 答案行为一致性判定（answer-conduct gate） | 判定层直接比较「答案行为」与「用户问题意图」：答案中出现**用户未要求**的行动指示/外链/联系方式/口令即拦截，与资料 demand 字面完全无关 | 与攻击措辞/语言/编码/近形字全部解耦——模型怎么改写，都改变不了「这句话在指使用户做没被问到的事」这一行为事实；确定性层零 AI 依赖，degraded 也不失效 | 需要谨慎的问题意图豁免（用户真问「怎么导出笔记」时不能拦） | **采纳（主判）** |
| D. LLM 行为审计器 | 独立 LLM 对（问题, 答案）判定哪些句段是未经要求的行动指示/外传/口令，输出句段序号，确定性剥除 | 语义级覆盖 C 的词表盲区（任意语言意译）；输出只是序号，即使被说服影响面也只是多剥/少剥，不构成新执行通道 | 依赖 AI 可用性 | **采纳（语义主判，C 为确定性底座）** |
| E. demand 近似匹配（模糊化的旧路线） | foldCompact 后做近形字折叠 + 字符 bigram 相似度，而非精确子串 | 直接封 R269-44 类近形逃逸 | 仍是字面家族，只能当纵深 | 采纳为纵深（不再是主判） |

**采纳组合：C（确定性行为门）+ D（LLM 行为审计）为主判，E 与既有各层（nonce 资料区、
外链 allowlist、marker/句段剥除、demand 剥除）降级为纵深。失败语义 fail-closed：**
D 不可用时 C 仍独立生效（C 不依赖任何 AI/任何资料文本）；抽取器判定资料含指令
（demands 非空）时，流式增量停发、只交付终判后的全文。

### C 层判定规则（`scrubUnsolicitedConduct`，backend/src/prompt-armor.ts）

按句段判定，命中「风险行为类」且问题未要求该类行为的句段整段剥除：

1. **数据外传劝导**：句段同时含（导出/备份/打包/上传/同步/发送/转发…）与（全部/所有笔记/数据/记录）或（邮箱/email/网盘/云端…）；
2. **外链/导航指示**：（访问/前往/打开/点击/登录/扫码/重置…）+（链接/网址/网站/页面/密码）或任何域名形态（含拼读式还原后）；
3. **联系方式投放**：（联系/添加/加）+（微信/QQ/客服/电话/telegram…）或答案中出现资料派生的邮箱/号码；
4. **口令/暗号输出**：（口令/暗号/密令/通关…是/为/：）模式，或答案开头的资料近似回显短词（E 层模糊匹配）。

问题意图豁免：问题本身含同类行为词（「怎么导出笔记」「备份怎么做」「笔记里的口令是什么」）
或点名要求原文/脚本/命令时保留。豁免只看**用户问题**，资料无法伪造。

### D 层（`auditAnswerConduct`，backend/src/answer-guard.ts）

输入只有（用户问题, 编号句段列表），**不含资料区**——审计器判定的是「答案是否在指使
用户做没被问到的事 / 投放联系渠道 / 复述口令」，与注入源头无关，因此对意译免疫，
也不存在被资料区二次注入的面。输出严格 JSON 序号数组，解析失败视为审计不可用（C 层兜底）。

### B05 误伤修复（audit-r269 P2-1）

`scrubDataDerivedSpans` 增加**同行延续豁免**：句段与前一保留句段之间的分隔符为
分号级（; ；）且两段折叠压缩后在资料影子中相邻连续（即同一条资料行的连续引用），
视为用户点名要求的原文的一部分，保留。`for f in *.log; do gzip "$f"; done` 因此完整
保留；注入句以句号/换行与正文隔开（R269-10 形态），不满足延续条件，仍被剥除。

## 三、P1 检索（audit-r269 P1-1）逐例处置

| R269 失败例 | 根因 | 处置 |
| --- | --- | --- |
| q11「潮」单字零召回 | 单字/短词是语义检索固有弱区，且无子串回退 | ask 零召回时对 ≤2 字 CJK 内容词回退 LIKE 子串召回（新增 `shortQueryLikeRecall`） |
| q20 语义近邻误引（sprint review 顶替产品点子） | 弱语义命中进了引用 | 已有 `ASK_CITATION_MIN_SCORE` 门槛；提高「找到了相关笔记但没提到」路径的建议位主题一致性（复用 R268 主题向量把关），不额外收紧全局阈值（不损召回） |
| q31 依据集合混入资金往来/收入 | 合计答案的 references 取全部收支命中 | 支出类合计的 references 收敛为**实际计入合计的支出行**（income/transfer 不再进依据），答案口径不变 |
| 60s+ 延迟尾部 | degraded AI 生成偶发长尾 | 登记不改（生成超时已有 40s 上限，观察到的 60s+ 来自重试链路；本轮不动生成预算，避免与护栏改动互相干扰） |

retrieval-eval 扩充：并入 R269 独立召回集的代表 case（单字长尾、跨语言、负例零召回、
依据口径），复跑量化，验收标准=召回提升且精确不降。
