## 5. 分级发现

### P1（影响核心主线，建议下轮优先修）

- **P1-1 生产 Service Worker 长期停留 installing 未激活，离线缓存不可用**。【浏览器实测】多次刷新/重进，SW 始终 "trying to install"，无 active worker、无 controller；设置页长期显示「离线缓存正在安装中」。影响：R166 引入的离线可用能力在生产实质失效，且无失败可见性/超时兜底。影响核心主线（可靠找回的离线兜底）。缓存身份 scrub 因在应用层（main.tsx）不受影响。
- **P1-2 多行 CSV 记账合计回归（R170 P1-2 行为漂移）**。【生产实测】UTF-8 4 行记账 CSV（199+99+38+20）→ 分类 expense 但 `amount=null`，356 元完全未进财务统计；GBK 2 行记账 CSV → 分类 data 不入账（买菜 55.5/地铁 4 丢失），仅生成式问答从原文捞到。`parseTriageJson` 的同类同币种求和逻辑（`backend/src/triage.ts`）在生产模型输出下未生效。影响核心主线（AI 整理→财务口径漏账）。
- **P1-3 自然措辞主题极值答错数字**。【生产实测·3 次复现】「键盘里最便宜的是哪一把」→ SSE/LLM 路径答「MX Keys 599 元」（正确答案 Keychron K3 458）；而「我买过的键盘里最便宜的是哪一把」「键盘里最便宜的花了多少钱」走确定性路由答 458 ✅。同族证据：多轮概括把 458 说成"第二贵"。即确定性极值路由触发词覆盖不足时，LLM 兜底路径会给出错误比较结论——直接违反忠实性红线（数字错误而非拒答）。`extreme-repro.log`。影响核心主线（可靠找回）。

### P2

- **P2-1 财务主题关键词提取过拟合致 fail-closed 找回失败**：「HHKB键盘」「咖啡上的」「的机票去哪的」(sse q7) 等 LIKE 词直接从问句切片，命中 0 后拒答，可找回数据被判"没找到记账记录"。诚实但伤找回体验。
- **P2-2 「记了哪些收入」误路由为全笔记枚举**（faith f27），收入列举意图未被财务列举路由接住。
- **P2-3 四档字号功能缺失**：审查纲领将其列为终检项，但产品无字号设置；需求与实现不同步（要么补功能，要么修订验收清单）。
- **P2-4 快速记录 textarea / 搜索输入缺可访问名**（仅 placeholder），读屏用户不友好。
- **P2-5（观察）`GET /api/notes` 偶发极端慢**：分拣高峰期一次列表请求耗时数分钟级（QA 期间两次遇到，未系统计时），怀疑与 triage 队列/D1 竞争有关，建议加观测。

### 设计建议（本轮 2 个未审过流程的深挖质疑）

**D1 Service Worker 安装/离线缓存生命周期（未审过流程）**
现状：SW 注册后若安装长期不完成，无超时、无失败态、无重试策略；UI 永远显示「正在安装中」，用户与运维均无从知晓离线能力已失效（本轮 P1-1 即此设计盲区的直接后果）。质疑：这真的最适合吗？离线是"兜底能力"，兜底自身失败必须可见。建议：① install 阶段预缓存加超时/分片，失败进入明确的 degraded 状态并上报；② 设置页展示 SW 真实状态（waiting/active/失败原因）而非单一"安装中"；③ 版本升级用 skipWaiting+受控刷新，避免僵尸 installing。高内聚：SW 状态机收敛在一个模块，UI 只订阅状态。

**D2 确定性财务路由与 LLM 兜底的分界·主题词提取设计（未审过流程）**
现状：主题极值/合计等确定性路由靠正则触发 + 从问句切片出 LIKE 关键词；触发失败则整题滑入 LLM 生成路径。两个后果本轮都实测到：词切错 → fail-closed 误拒（P2-1）；触发不了 → LLM 自己比大小算错（P1-3）。质疑：把"是否走精确统计"押在词法正则上，是否真的最适合？数字正确性是产品红线，不应随措辞漂移。建议（按"如无必要勿增实体"取最小方案）：① LLM 兜底路径遇到财务比较/极值类问题时，强制先调确定性统计做证据再生成（工具化，而非自由比较）；② LIKE 词提取失败时回退到检索命中笔记的标题词而非问句切片；③ 对"哪些收入/支出"类列举意图补充触发词。这样确定性口径成为唯一数字来源，LLM 只负责措辞。

## 6. 「可公开推广」GO/NO-GO 复评

**结论：NO-GO（暂缓），距 GO 仅一步。**

- 达标面：忠实性核心红线（0 幻觉、0 敏感泄露、已答数字准确）连续两轮保持；R176 两个 P1 修复在生产验证成立；Lighthouse 双端近满分；键盘/暗色/敏感遮罩合格；剪藏幂等、伪装文件兜底健壮。
- 卡点（公开推广前必须处理）：
  1. P1-3：自然措辞下答错金额（599 vs 458），对外推广后属最伤信任的一类错误；
  2. P1-2：CSV 记账漏账，"什么都能丢"承诺打折；
  3. P1-1：离线能力生产失效且不可见。
- 判定逻辑：三个 P1 都在核心主线上；修复+复测通过后即可转 GO（预计一个短周期迭代量）。
