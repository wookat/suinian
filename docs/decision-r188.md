# R188 修改轮决策记录（落实 audit-r187）

对应审查报告：`docs/audit-r187.md`（R187 终定 GO）。本轮清 1 个 P1 + 2 个 P2，其余建议逐条评估。

## 1. P1-1 图片凭证链路断裂 → 修复（统一敏感管道）

R187 §5.1 实测断链：视觉抽取静默丢弃密码值 → 正文无秘密值 → 分拣判非敏感 → 原图不加密 → 问答找不到还谎称「已加密」。三层各自自洽、拼起来互相矛盾。

修复原则：图片来源内容走与文本完全一致的敏感识别/加密管道（`sensitiveIngestGate` / `applyTriage`），不新增平行加密逻辑。具体：

1. **视觉提示词三段式**（`media.ts`）：文字段要求逐行逐字完整转录（密码/密钥/验证码等值原样保留，禁止省略打码）；新增「敏感：是/否」段让视觉模型对「图中出现真实机密值」独立判定——文本分拣看不到像素，这是敏感信号的唯一无损来源。temperature 降至 0.1 抑制 R187 §3 观察到的同图两次抽取差异。
2. **敏感口径 = 视觉判定 ∪ 文本检测**（`parseImageExtraction`）：任一命中即敏感。视觉判敏感但文字段未见凭证值时，正文如实标注 `IMAGE_CREDENTIAL_GAP_NOTICE`（「文字可能未完整提取，可打开原图查看」）——不再把抽取缺陷包装成安全特性。
3. **入库走统一管道**（`imageNoteFields` → `prepareNoteInsert`/`replaceNoteContent` 的 `is_sensitive` 提示）：API `/api/ingest/media`、微信、企微、retry-media 四条图片路径全部复用同一映射，敏感则正文 AES-GCM 加密（`content_enc`）、附件同步加密（既有 `storeOriginal`/`syncAttachmentEncryption`），无新实体。
4. **`meta.vision_sensitive` 粘性标记**（`types.ts`/`note-store.ts` `applyTriage`）：异步文本复判只看正文，正文可能恰好没有秘密值（值在原图里）；带此标记的笔记复判不得解除敏感位。派生明文（`image_description`）由既有 `scrubDerivedMeta` 洗净。
5. **回执/问答口径**：敏感媒体回执与 API 响应不回显抽取内容；问答凭证兜底话术补充「拍照记的凭证还可打开笔记里的原图确认」，与 count-only 口径一致。

回归：`backend/test/r188-fixes.test.ts`（凭证保留/缺值标注/视觉∪文本并集/粘性复判/meta 洗净/回执不回显），全量 1067 测试通过。

## 2. P2-1 小票金额双计 → 修复（三层统一金额口径）

R187 §3 实测：明细（12.5+8.0+15.8）与「合计 36.3」同加记成 72.6。口径统一为**有明确合计时 amount=合计值**：

1. 提示词判例（`triage.ts`）：合计/总计/实付出现时明细与合计是同一笔交易。
2. 多对象输出总额检测（`parseTriageJson`）：≥3 笔同类同币候选中若有一笔恰等于其余之和（±0.005），取该总额而非叠加；两笔不检测（a+b 无从判别），无总额关系仍求和（不回归 R170 多行账单）。
3. 确定性兜底：表格合计行（`parseLedgerCore`，多个合计行歧义则不猜）+ 散文合计 2T 校正（`fixReceiptDoubleCount`，仅当模型金额≈2×声明合计时锁回合计值）。

回归：合计行/实付/折扣/无合计多行求和/歧义/散文 2T 共 15 例。

## 3. P2-2 聚类召回保守 → 调整（floor 0.62→0.58 + 带内 top-3 逐一确认）

离线 A/B（`scripts/thread-recall-eval.ts`，60 条受控语料 8 主题+16 干扰项，bge-m3 + llama 确认，与生产同规则）：

| 策略 | pair 精确 | pair 召回 | 未入线索 | 确认调用 |
|---|---|---|---|---|
| A 现行（best-1, floor 0.62） | 92.9% | 12.9% | 78.3% | 8 |
| B top-3, floor 0.62 | 92.9% | 12.9% | 78.3% | +8 |
| C **top-3, floor 0.58（采纳）** | 88.2% | **29.7%** | 56.7% | +19 |
| D 现行+线索合并 | 92.9% | 12.9% | 78.3% | +8 |

失召主因是 below_floor（28/47）：同主题真实措辞变化下相似度大量落在 0.52–0.61 带，floor 0.62 直接排除、连确认机会都没有。仅升 top-K 不降 floor（B）零收益。采纳 C：召回翻倍（12.9%→29.7%），精确降 4.7pp 仍高于 R187 生产实测线索精确 81.8%；误合由确认模型兜底，成本上限 3 次确认/条且命中即止。这同时解释 R187 重度账号 62 条仅成 1 线索的现象。R106 曾否决的是**无确认直连**的 0.5 裸 floor（59.3% 精确），与本次「降 floor 但每条都过 LLM 确认」不同。

实现：`threads.ts` `SIM_CONFIRM_FLOOR=0.58`、`CONFIRM_TOP_K=3`，直连（≥0.76）逻辑与 R150 已有线索优先规则不变。
