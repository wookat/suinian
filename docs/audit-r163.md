## P1-1 AI 标题让零语义笔记的向量借道复活，仍污染线索聚类

**影响核心主线：是（AI 整理为主，间接影响可靠找回）**

【生产实测】
- 纯 emoji 笔记 `🎉🎉🎉`（AI 标题「庆祝」）、`😭😭 💪`（「当前情绪」）、`！！！👏👏👏`（「庆祝」）三条
  note_embeddings 均为非空真实向量（长度 19461~19520 字节），且 thread_id 全部指向同一条 63 成员的有效线索
  「生活节奏与个人成长」；该线索摘要含「庆祝」「碎念」等无信息量碎片。
- 对照组 `。。。。。`（无 AI 标题）：向量为哨兵空值（长度 2），未入任何线索——证明 R162 的
  `hasSemanticSignal` 闸门对"原文+标题都零信号"的路径是生效的。

【源码】根因：`semantic.ts` 的 `hasSemanticSignal` 只检查文本是否含 Unicode 字母/数字；而
`noteEmbedText` 把 `title/content/url_title/url_summary` 拼接后作为嵌入输入。AI 分拣（triage）会给
纯 emoji 内容生成**文字标题**（如「庆祝」），拼接结果因此含字母/数字、通过闸门。R161 P1 修的是
threads.ts 绕过闸门的旁路，R162 统一了闸门入口，但**闸门检查的对象（拼接后文本）与污染源（AI 生成的标题）
在同一条流水线上**，等于闸门装在了污染源下游。

修复建议：闸门应检查**用户原文**（content + url 原文）是否有语义信号，而非拼接后的文本；原文零信号的笔记
即使有 AI 标题也不参与嵌入/聚类（标题只用于展示）。一行判断的位置问题，属"高内聚"教训的延续：
上一轮把两个写入口合成一个，这一轮发现合并后的入口检查错了对象。

对照正向指标（不受影响）：
- 有效语义笔记聚类/检索正常：19 条线索主题清晰（咖啡烘焙、健身计划、日语学习等），
  `我学做糖醋排骨的心得是什么` 问答准确带引用【生产实测】。

## P2-1 剪藏扩展同页重复剪藏无去重，与导入/恢复的去重口径不一致

**影响核心主线：轻微（什么都能丢·数据卫生）**

【生产实测】真实 Chrome 加载生产构建扩展（MV3），对同一 MDN 页面执行两次"保存整页"→ 产生两条独立笔记
（API 回查可见 `Fetch API - Web APIs | MDN` 两条）。而 zip 导入/恢复路径有 import_fp v1 指纹去重
（同 zip 二次恢复 327 条全部 skipped，见附录 C）。同一产品内"重复内容是否合并"存在两套口径。

设计质疑：扩展剪藏是"随手丢"场景，允许重复可以理解；但同 URL+同内容的整页剪藏几乎必然是误操作或
"忘了已存过"，静默产生重复会随时间稀释线索质量（重复成员会一起被聚类吞入）。
建议：整页剪藏命中同 URL 未删除笔记时，通知栏提示"已存过，点击查看/仍要再存"，而非静默新增。

## 设计质疑（2 个未审流程深挖）

### 1. 凭证生命周期：token 轮换与恢复码找回

【生产实测，QA-C】
- `POST /api/auth/rotate-token`：旧 token 立即 401，仅存唯一新 token——泄露凭证即刻全域失效，通过。
- `POST /api/auth/recover`（用户名+一次性恢复码+新密码）：旧 token 401、旧密码 401、新密码/新 token 生效、
  **旧恢复码立即失效**（复用 → 401 统一文案「用户名或恢复码错误」，无账号探测面）、返回新恢复码。整条链路无懈可击。
- 质疑点：恢复码是找回账号的**唯一**途径（无邮箱/手机绑定），注册时仅展示一次。密码+恢复码同时丢失 = 账号
  永久失联，而本产品定位是"什么都能丢"的记忆外脑，数据情感价值高。这是隐私（零联系方式）与可恢复性的
  权衡，当前取舍可辩护；建议（设计建议 1）：在设置页对"未确认保存过恢复码"的账号做周期性温和提醒，
  或提供恢复码已抄写的确认打卡，把单点失联风险显性化。

### 2. 敏感明文导出的授权强度

【生产实测】`GET /api/backup?include_sensitive=true` 仅凭长期 bearer token 即可导出**全部敏感明文**
（含解密后的信封加密附件），无任何二次确认。【源码】backup 路由无 password 复核逻辑。
- 该 token 同时长期驻留在浏览器扩展 `storage.local`（明文）与 Android 本机——任一端点失陷即可静默拖走
  敏感明文全量包。而产品其余部分对敏感数据处处设防（搜索不露明文、问答拒答、导出默认脱敏），
  唯独"整包带走"这一最高危操作与普通读接口同权。
- 设计建议 2：include_sensitive=true 时要求随请求提交密码复核（或签发 5 分钟短时确认票据）；
  成本一行校验，把"泄露 token"与"泄露全部敏感明文"两级风险重新隔离开。

### 3. 问答引用的重复主题并列（顺带观察）

【生产实测】问答对同主题多条重复笔记并列多引（糖醋排骨 3 引），答案正确但引用面冗余；
与 P2-1 同根：写入端不控重，找回端就要替用户去重。设计建议 3：引用列表按内容指纹聚合展示。
