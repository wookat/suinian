【源码检查】归因（`backend/src/ask.ts`）：`financeListIntent` 先要求 `FINANCE_LIST_CUES` 命中，再剥离残词。PR #279 只加长了剥离表，没有放宽 cue：

- 支出 cue 里能覆盖前缀式列举的是 `列(?:一下|出|举)?[^？?。]{0,6}(?:支出|开支|开销|花销|消费)`——要求「列」在关键词**之前**且间隔 ≤6 字，所以 `列出我所有支出` 命中，而 `支出列出来`（语序倒置）、`你把全部支出列出来`（「列」在关键词后）不命中。

影响：R252 主诉「框架词剥净」只在部分语序/方向上成立，等价语义的自然问法仍落通用兜底。评 **P2**（可用性缺口，无数据错误）。

### P2-1 退票类句式产出负金额收入【生产实测】

- 输入：`[QA-R253] 机票退票，退回 1130 手续费扣了 200`
- 落库：`category = income`，`amount = -930`（预期 `+930`，符号取反）
- **污染聚合**：账号 b「这个月有哪些收入」→ 逐笔明细含「机票退票（¥-930）」，本月收入合计 `¥5584.50`；按正确符号应为 `¥7444.50`，收入被低估 ¥1860。「这个月我一共花了多少钱」同样使用该被污染的收入数。
- 附带观察：直接问「机票退票退了多少」→「退了 1130 元，手续费扣了 200」（原文引用正确），说明是分拣阶段的金额抽取符号问题，不是检索问题。
- 评级理由：收入类目出现负金额本身就是口径错误，且直接进入对外的精确统计数字（产品把这些数字标注为「精确统计，口径与周报/月报一致」），属数据正确性问题，评 **P2**。

- 复现：`今天收到了哪些钱` × 3 → **3/3** 全部回答「今天你共记了 26 笔支出：… 支出 ¥5116.40 …」，把用户问收入答成全量支出清单；UI 走查独立复现 1/1（截图见 §7）。

- 【源码检查】归因：`FINANCE_LIST_CUES` 的支出模式包含裸 `哪些钱`（`/花了?(?:哪些|些什么|什么)钱|哪些钱|钱(?:都)?(?:花|用)(?:在|到)了?(?:哪|什么)/ → expense`），而收入模式没有「收到…钱」的对应式，于是「收到了哪些钱」先被支出 cue 抢中，方向判定为 expense。

## 结论与建议（供 R254 修方参考，本轮不改代码）

1. **P2-1（优先）**：退款/退票类句式的金额符号。建议在分拣金额抽取后加一道口径校验：`income` 不允许负金额（负值应改判 `expense` 或取绝对值 + 记净额），并补 eval case 覆盖「退回 X 手续费扣了 Y」。
2. **P2-2**：给收入方向补「收到…钱 / 收到哪些钱 / 到账了哪些钱」cue，并让裸 `哪些钱` 的支出 cue 让位于显式收入动词（`收到/进账/到账/收`）。
3. **P2-3**：`financeListIntent` 的瓶颈在 cue 而不在剥离表。建议把「列举动词 + 方向词」解耦成「方向词命中 + 列举意图命中（任意语序）」两个独立判断，并把收入方向补齐 `列(出|举|一下)…收入`。
4. **P3-1**：跨双窗对比问法建议至少降级为「分别给出两个窗口的合计」，避免出现「上半年没有找到相关记录」这种与事实相反的读感。
5. **P3-2 / P3-3 / P3-4**：品类归纳、口语化结余、「X相关的支出」语序，属召回覆盖缺口，按优先级排入。
6. **P3-5**：敏感判定口径建议区分「凭据本身」与「凭据的存在提示」（如只有 Wi-Fi 名称、会员号），减少可检索性损失。

**GO/NO-GO：GO（有条件）** —— 无 P0/P1，安全与隔离边界全绿，全量 eval 100%，R252 主诉修复真实生效；条件是 P2-1（财务口径正确性）与 P2-2（方向错答）建议在下一轮优先修复后再大规模推广财务问答场景。
