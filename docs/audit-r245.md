## 专项 2：SW 注册失败横幅重新归因（本轮重点）

**矛盾**：R243 定案"浏览器侧间歇，25/25 零复现"，但 R242/R244 两轮 QA 都持续看到横幅。

**证据链（本轮新采）**：
1. `sw.js` 可达性/MIME/缓存头【生产实测】：3 次抓取均 HTTP 200，`content-type: application/javascript`，`cache-control: public, max-age=0, must-revalidate`，`x-content-type-options: nosniff`，ETag 稳定 → Pages 部署侧无缺陷。
2. 注册矩阵 50 次 0 横幅【生产实测】：无头新档案 ×30（20+10）、模拟 Devin UA ×10、常驻 Devin Chrome（真实 QA 环境同款）×10，全部 register() resolved、SW active、无横幅。
3. UI 实测【生产实测】：常驻 Chrome 首次加载 + 硬刷新（更新路径）均无横幅（见录屏）。
4. 实时 Workers Logs 窗口（约 40 分钟，覆盖上述矩阵）：真实用户 sw-error 上报 0 条；唯一 1 条上报是本轮故障注入产生的【生产实测】。
5. 故障注入模拟【模拟】：浏览器级 CDP Fetch 拦截 sw.js → 横幅立即出现，文案正确；解除拦截后 30s 首次自动重试成功，横幅自动消失，SW active，上报到达 Workers Logs。注意：页面级拦截无法拦到 SW 脚本请求，需浏览器级——这也说明 SW 脚本请求走独立网络路径，对本地代理/网络瞬断比页面请求更敏感。

**重新归因**：两个"矛盾"证据其实兼容——
- R243 的 25/25 与本轮 50/50 测的是**网络正常时的注册成功率**，结论可靠：生产部署无缺陷。
- R242/R244 QA 看到的横幅是**真实横幅**，但触发者是 QA 会话本地浏览器到 Cloudflare 的瞬时网络故障（SW 脚本请求独立于页面请求，代理环境下更易单独失败）。repo 测试技能库也记载了"QA 环境浏览器请求会间歇性挂起"的已知现象。
- 该失败**自愈**（30/60/120s 重试），且**不影响在线功能**（横幅文案如实说明）。实时日志窗口 0 条真实用户上报，未见真实用户受影响的证据；历史 7 天聚合量因 telemetry API 权限无法程序化核查【未验证】，建议下轮在 dashboard 人工确认一次。

**评级**：不构成产品缺陷，不开新问题单。改进建议（可选，P3 级）：把 sw-error 上报同时落 D1 计数表，使审计可用现有 token 程序化核查历史量，彻底关闭 F-4。
