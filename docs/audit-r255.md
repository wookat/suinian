### P1-1 详情（本轮唯一 P1）

问题：`我给女朋友买过什么礼物`
回答：`你给女朋友买过的礼物有：《长安的荔枝》[1] 和 《置身事内》[2]。`

事实：该账号 21 条笔记（种子脚本可查）中**没有任何一条包含「女朋友」或「礼物」**，两条被引用的笔记原文分别是 `[QA-R255] 买了《长安的荔枝》38元`、`[QA-R255] 买了《置身事内》52元`（标签 `买书`）。同一批 30 问中的其它无答案题（`我的猫叫什么名字`、`我的车牌号是什么`、`我有没有记过房租`）都正确 fail-closed，说明兜底路径本身是对的，本例是 LLM 生成环节把「买过的书」当作「给女朋友买的礼物」补足了不存在的关系。

影响：用户会认为系统「记得」他没记过的事实，且带引用更具说服力。对照 R253 忠实性 30 问幻觉 0，属回归。

建议（R256 修方）：无答案判定不能只看召回是否为空——召回命中但问题包含笔记中不存在的**关系限定词**（人物/用途/对象）时应降级为「找到相近记录，但没有记到与『女朋友』相关的信息」，并把该类问题补进 eval（`forbidAnswerContains`）。

### 1.3 R253 无回归 + ask-eval 引用完整性 miss 归因

- 全量 ask-eval（`--holdout`，生产账号自建自删）：**185/185（100%）**，21 个类别全绿，含历史挂账题 q24 / q31 / q49 / q52 / q56 全部通过【生产实测】`ask-eval.log`
- 引用完整性 miss 归因【源码检查 + 生产实测】：
  1. 185 题中 24 题 `refs=[]`，逐条核对**全部是**「无记录 fail-closed」「统计聚合（计数/均值）」「时间窗内零命中」「极值无命中」类——这些答案按设计不需要引用，不是引用缺失；
  2. `backend/scripts/ask-eval.ts` 里 `citeHit` 被计算却既不参与 `pass`、也不进 `report()` 输出（`pass = recallHit && allHit && refusalOk && forbidOk && answerOk`）。因此「引用完整性 miss」在现有评测口径下**结构性不可见**，历史 miss 项无法从 100% 的结果反推是否修复 → 记为 P3-4，建议把 `citeHit` 输出为独立指标（不必立即纳入 pass）。

## 10. 结论与建议（供 R256 修方参考，本轮不改代码）

1. **P1-1（最优先）**：关系限定词（人物/对象/用途）不在召回文本中出现时，生成环节必须降级为「没有记到与『X』相关的信息」，禁止把相邻实体补成关系；同时给 eval 增加 `forbidAnswerContains` 类幻觉题。
2. **P2-1**：`本月支出和收入分别多少` 这类「方向并列 + 分别」句式应进确定性聚合路由（`工资到账后这个月净剩多少` 已能进，说明路由表缺 cue 而非能力缺失）。
3. **P2-2**：双窗对比至少降级为「分别给出两窗合计」，杜绝「上半年没有找到相关记录」这种与事实相反的读感（R253 P3-1 已挂账两轮，建议本轮闭环）。
4. **P2-3**：财务列举与主题限定要能叠加——`列一下买书的支出` 应走「关键词匹配 + 列举」，而不是丢掉限定条件回全量。
5. **P3-1**：关键词匹配的最小长度限制导致单字主题（书/车/药）失效，建议对单字词放宽或走标签匹配。
6. **P3-3**：关键词合计的「标签命中不计入合计」口径建议改为默认计入并标注来源，减少「同一批买书结果不一致」的困惑。
7. **P3-4**：ask-eval 输出 `citeHit` 独立指标，让引用完整性缺口可见。
8. **P3-5**：明确 `/api/ask` 限流阈值与窗口，并在文档/QA 技能里固化，避免评测被限流干扰。

**GO/NO-GO：GO（有条件）** —— 无 P0；R254 主诉修复全部真实生效，R253 两个财务口径 P2 已闭环；安全 / 隔离 / 备份恢复 / 数据健康 / 性能五面全绿且性能优于历史基线。条件是 **P1-1 幻觉与 P2-1/P2-2 与事实相反的空答修复后再放量公开推广**。
