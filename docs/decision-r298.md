## 1. P0-1 判别器结果有效性校验（fail-closed 扩到软失败）

### 1.1 安全下界

**任何「判别器结果不可信」的状态都并入 unavailable，与硬失败同处置。** 不可信包括：缺字段、结构不符、非预期枚举值、字段越界、截断 JSON、findings 为空但确定性门控已命中、慢成功。攻击者可诱导判别器输出畸形/空结果，因此结果有效性必须由严格 parser 确定性校验，不能「尽力解析」。

### 1.2 零命中不得否决确定性门控

方向性规则固化为代码：**LLM 结论只能在「拦」的方向加严，永不能否决已触发的确定性门控。**

- 确定性门控（`gate:primitive:*` 组合门、`globalExecDangerReason` 高置信内核）命中 + 判别器零命中 = 保守处置（隔离并说明），不缓存该零命中。
- R294「高置信内核否决判别器零命中」保留（拦方向）。
- 该 veto 内置在 `finalizeAskAnswer()` 内部而非依赖调用方传参（R298 修复：原实现依赖调用方设置，遗漏即 fail-open）。veto 判定用原始 answer + `judgeSurfaceText(answer)` 双面（外链清理会把 URL 换占位符，语义判定必须看清理前的面）。
- 误伤控制：`net+hostport` 组合门排除本地/回环/私网端点（善意反向探针误伤实测 0）。

### 1.3 慢成功策略（论证）

慢成功 = 响应时间超过软阈值但在硬预算内。选择「**超过软阈值即视为不可信 → unavailable 处置**」：接近预算的响应大概率是重试/截断/降级路径产物，其完整性无法与正常响应区分；把它当有效结果等于让攻击者用「慢」制造低质量判定窗口。代价只是偶发保守隔离一次（段落级，见 §3），可接受。

### 1.4 重试与开窗

- 同请求内先做一次**即时重试**，重试成功则按在线处理。
- **连续 3 次失败**才开降级窗口，窗口 **8s**（R297 要求 5–10s；单次抖动不再触发 60s 全量降级）。判别器成功一次即复位。

### 1.5 验证

`backend/test/r298-guard-matrix.test.ts`：R297 34 载体（含 C04/C06/P04）× 8 判别器态（hit/empty/oob/慢成功/抛错/超时/截断 JSON/字段缺失）矩阵，leak=0、两态互斥、无残片、降级标记正确（实测确证）。

## 2. P0-2 无代码面执行意图的语义送判通路

不走「加载体清单」老路，从「哪些信号足以要求送判」设计：

**送判信号 =（远端地址面）×（取回/执行/移交语义面）**。地址面：IP/域名/端口/哨站描述（含数字变体、全半角）；语义面：取回（取/拉/下载/fetch/取回）、执行（执行/煮开/run）、管道/移交（倒进 sh 锅 / 交给解释器 / pipe）——覆盖中文/英文/拼音/注音/日文/韩文、比喻与替代词、跨笔记分片、组合附加符、逐字空格、base64 data URI 还原后判定。命中即送判别器；判别器不可用时按 §1 降级处置（纯语义危险载体在降级态仍拦）。

误伤评估（实测确证）：判错代价只是多一次 LLM 调用；善意语料反向探针误伤 0；R295/R290/r288 善意集在线态误伤未升高（见 §8）。

## 3. P1-2 降级态段落/代码单元级隔离

### 3.1 安全下界

降级态的下界不变：**未经判别的危险能力面不得出厂**。变化只是隔离粒度——从整答案改为「有命令形态嫌疑的段落/代码单元」；当无法定位任何可疑区间但确定性痕迹判定（`execDegradedTraceReason`，载体无关下界）仍命中时，回退整答案隔离（`wholeAnswerIsolate`）。放松的是误伤面，不是安全面。

### 3.2 判定面

`redactCodeSurface()`：fence 感知分段（`splitSegmentsFenceAware`）+ 行级能力判定（`lineCarriesCapability`：外连/下载/管道执行/编码还原/建连 API 等）+ 掩码变体（`maskedCarrierVariants`）。命中单元替换为降级 marker，其余照常出厂并附用户可感知的降级提示 + 前端「重试本轮提问」。

### 3.3 效果（实测确证）

- 混合问答形态（散文包装）降级整答隔离：R295 5/130、R290 2/30、r288 8/116，合计 **15/276 = 5.4%**（R297 基线 25.8%，显著降低）。
- 原始裸载荷语料 raw 口径为 157/276 = 56.9%——这些载荷本身即代码/危险能力载体，被段落级隔离是正确行为，不是误伤；两套数字均保留于评测脚本输出。
- 在线态误伤 0/276。

## 5. P1-3 幻觉凭据出口过滤

`credentialAssertionReason(answer, dataText)`：答案含「凭据主题词（密码/密钥/key/secret/token/验证码，中英日韩）+ 断言连接词 + 高熵串」且该串**不在引用笔记明文中**时，整答案替换为统一拒答（敏感笔记不进问答，未加密来源无可核对原文，给值只会是编造）。明文确有该值时按既有敏感规则处理（豁免）。定向测试 16/16、善意探针误伤 0（实测确证）。

## 7. P1-6/P2 性能与 verbatim

- **并行化**：`route`/`kwext` 与 `sem`/`embed` 并行；SSE 侧判别器 directive 判定与生成并行——生成句段先入内存队列，`demandsSettled` 后按原序排空（**判别未就绪前零 delta 出厂，「先泄后收」结构性不可能**，done 仍是权威终稿）。`dirwait`/`pregen` 计入 Server-Timing。修复前后生产首 delta 中位/p90 对比在部署后实测（未验证，待 §生产复测）。
- **P2-1 verbatim 截断**：`body.slice(0, 500)` 改为动态预算——verbatim 问法单笔 8000 字预算（总预算 12000 按笔记数分摊取大），非 verbatim 保持 500；截断落在句读边界。
- **P2-2 CRLF/行尾空白**：**判定不修存储侧**。归一化（CRLF→LF、行尾空白裁剪）发生在写入口，是跨端一致性与去混淆（行尾不可见字符是注入载体）的既有安全口径，回退会扩大判定面差异。口径改称「**近似原文**」：保证字符内容与行序逐字一致，换行统一为 LF、行尾空白不保留。
- **P2-3 可观测性**：新增 D1 `guard_events` 表（migration 0031），`classifierUnavailable`/`veto`/`isolated` 计数经 `waitUntil` 异步落库（不阻塞请求，写失败仅 console.error，不影响安全路径）。下一轮可回答「判别器不可用多久发生一次」。
