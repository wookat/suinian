# R20 知识图谱层：前后效果对比报告

验证账号：QA 专用账号（`[QA-R20]` 前缀数据，验证后已清理，未触碰 u_boss 数据）。
数据集：21 条真实感碎片，跨三条故事线交织——「AI 简历教练」创业想法（想法/人物老周/收藏文章/待办/调研）、莫干山露营计划（想法/收藏/待办）、健身计划（想法/记录/收藏）。

## 1. 图谱抽取结果

- 21 条笔记全部完成抽取，产出 41 个实体、96 条边（60 条 mentions + 36 条实体间关系）。
- 核心连接实体被正确识别并归一：`AI 简历教练`（9 条笔记提及）、`老周`（6 条）、`莫干山`（3 条）、`猎头公司`（2 条）。
- 实体间关系示例：`老周 —属于→ 猎头公司`、`AI 简历教练 —相关→ 老周`、`真实岗位 JD 数据 —前提→ AI 简历教练`、`按岗位定制重写 —属于→ 重写方向`。

## 2. 线索聚类对照（旧法 vs 图法）

对同一批数据分别用 `POST /api/threads/rebuild {"mode":"similarity"}`（旧：纯向量相似度）与默认图法重聚：

| | 旧法（纯相似度） | 图法（图连通优先） |
|---|---|---|
| AI 简历教练故事线 | 拆成 2 条线索（「功能」4 条 /「优化」6 条），拆分边界随机（收费/模拟面试与微信小程序/数据合作被切开） | 仍为 2 条线索，但边界更贴实体语义（产品功能类 vs 落地开发类），且「英文模式」通过共享实体归入开发线索 |
| 跨故事线污染 | 无 | 修复后无（修复前曾把「健身计划」错并入 AI 线索，见 §4 教训） |
| 线索详情可解释性 | 只有笔记列表 | 新增「实体与关系脉络」：实体标签 + `AI 简历教练 —相关→ 老周`、`老周 —属于→ 猎头公司` 等关系链 |

结论：小数据集上聚类分组本身差异不大（相似度在同话题笔记上已经较强），图法的增量价值主要在 (a) 归组边界更贴实体而非表面词汇，(b) 线索的实体/关系脉络可解释，(c) 为问答提供了跨线索的连接通道。

## 3. 问答对照（GraphRAG 1 跳扩展 on/off）

同一问题分别 `{"graph":false}` / 默认（on）：

**Q1 我为什么想做 AI 简历教练？依据是哪几条笔记？**
两者都能召回痛点笔记；graph on 的回答把「老周的建议支撑这个方向」的支撑链说得更明确（依据 `老周建议 —支撑→ 重写方向` 三元组）。

**Q2 老周和我的哪些计划有关系？**（跨故事线人物问句）
- off：列出 4 项（一页纸/数据合作/露营/建议）。
- on：**多找回 1 项**——「微信小程序冷启动用老周的猎头人脉圈」，该笔记正文没有出现「计划」等关键词、语义相似度也不高，是沿 `老周` 实体 1 跳扩展带回的（上下文中标注「图谱关联」）。

**Q3 做 AI 简历教练的前提条件是什么？调研得怎么样了？**
两者都能答出「真实岗位 JD 数据是前提」+ 反爬调研进展；on 的版本引用更聚焦（直接引 premise_of 关系对应的两条笔记）。

结论：召回本来就命中的问题两者相当；**跨碎片关系问句（Q2 类）图谱扩展有真实增益**，且回答能标注关联依据。

## 4. 过程教训（已修复）

1. 抽取 prompt 未排除标记词时，`[QA-R20]` 前缀被抽成高频实体，成为"万能连接点"，曾把健身笔记错并入 AI 线索。修复：prompt 明确排除方括号标记与时间词。
2. 单共享实体入组的旧规则过松（只要用户图里存在任一强边即通过）。修复：单实体匹配时要求强关系边必须连接两条笔记各自的实体（双侧校验）。
3. 生产 worker 在验证期间被并行部署覆盖过（非本分支代码），复测时需确认线上版本。

## 5. 遗留与后续

- 线索仍按"先到先聚"贪心归组，同一实体的多条线索不会自动合并；后续可加定期"线索合并"任务（图连通分量）。
- 实体间关系以 `relates_to` 居多（LLM 保守），supports/premise_of 检出率有提升空间，可在 prompt 中加少样本示例。
- 若未来需要多跳推理/社区摘要，按 docs/graph-design.md 的路线 B 平移到独立 LightRAG/图库服务。
