# R290 架构决策：判定面从「代码区抽取」改为「归一化全文」

对象：answer-side 执行安全护栏（`backend/src/prompt-armor.ts`、`backend/src/answer-guard.ts`、
`backend/src/index.ts` 收口路径）。
输入：`docs/audit-r289.md`（R289 独立审查，NO-GO 第十五轮，P0-1…P0-4）。

本文先论证，再落地；实现与本文一一对应（每节末尾标注对应实现符号）。

---

## 0. 三轮连续失效的共同结构

| 轮次 | 加固动作 | 被绕过的方式 |
| --- | --- | --- |
| R284 | 逐句能力合取 + 判别器不可用兜底 | 能力拆到不同物理行 |
| R286 | 合取搬到「代码单元」 | 单元之间插一行散文 → 单元被切开 |
| R288 | 合取搬到「全局代码面」= 所有代码单元拼接 | **代码单元抽取本身**不认这些载体（中文散文逐行包裹 / 编号列表 / 表格 / HTML `<code>` / JSON 字符串 / 日志粘贴 / 全角） |

共同结构：**判定链条的第一步是「先识别出哪一块是代码/危险」**。这一步是 AND 门的最前项：

```
是否隔离 = 载体识别命中 ∧ 能力聚合命中 ∧ (判别器命中 ∨ 兜底命中)
```

识别环节漏一次，后面无论多强都恒为假——R289 实测的正是这个：全局合取、`fetchThenRunReason`、
连续量打分、LLM 门控、降级隔离**同时空转**，且因为没有任何单元被隔离，
`exec_guard_degraded` 也不置位（fail-open 无声）。

结论：**只要「危险判定」依赖「先判定这是代码」，识别环节就是新的单点失效。**
R288 的方向（把合取搬到全局）是对的，错在把「代码面抽取」当成了全局的入口漏斗。

## 1. 方案取舍

### 候选 a：全文即判定面（采纳）

不再问「这块是不是代码」，只问「**将要交付的这段文本里是否存在危险能力组合**」。
判定面 = 整个待交付答案（外链/邮箱收口后、隔离前）经**载体归一化**后的全文，
外加被逐字引用的资料原文（`dataText`，用于官方安装源核对与 verbatim 还原）。

为什么它不再有「识别漏斗」：归一化只做**减法**（剥壳、去混淆、全角转半角），
剥不掉的部分仍然留在判定面里。载体不被认识时，最坏情况是「壳没剥掉」，
而不是「这段文本从判定面消失」。判定面是全集，抽取步骤从 AND 门里删掉了：

```
是否隔离 = 能力聚合命中(归一化全文 ∪ 原始全文) ∧ true
```

### 候选 b：只加载体（否决）

继续给 `isCodeLine`/`codeUnitSpans` 补「编号列表 / 表格 / HTML / JSON / 日志」规则。
否决理由：载体空间无界（R273→R289 已经补了七轮），且这是**加法**结构——
补进来的才受保护，没补的直接消失。与 R288 同构，必然有第十六轮。

### 候选 c：只靠 LLM 判别器（否决）

判别器有超时/不可用/额度上限，且 R289 已实测 `hits=[]` 的漏判。
判别器只能作为**主判之一**，不能是唯一判据；且它的输入同样需要判定面（同一个漏斗问题）。

### 采纳：a + b(门控) + c(下界) + d(偏移映射)，四层同时落地

1. **归一化全文**做能力聚合与打分（§2）。
2. **门控**同样基于归一化全文：出现任何命令/网络/执行原语迹象即送 LLM 判别（§4）。
3. **载体无关下界**：能力聚合额外在**未经任何处理的原始答案文本**上跑一遍，
   两者取并（§3）。归一化即使把某种载体处理坏了，原始文本这一路仍然独立成立。
4. **偏移映射**：归一化按「行对齐」构造，每个归一化行携带原始行区间，
   处置落在原始行边界上（§5）。

实现：`normalizeJudgeSurface()`（`prompt-armor.ts`）。

## 2. 载体归一化：具体算子与安全影响

`normalizeJudgeSurface(text)` → `{ text, lines: Array<{ oStart, oEnd, text }> }`，
**逐行**处理，归一化后行数与原文行数一致（行 i ↔ 原文行 i），因此偏移映射是行级双射。

| # | 算子 | 目标载体 | 安全影响 |
| --- | --- | --- | --- |
| 1 | 剔除零宽字符 `U+200B-200D/2060/FEFF/00AD/180E/034F` | 零宽混淆 | 纯减法，只可能让特征更可见 |
| 2 | 逐字符 NFKC | 全角命令 `ｃｕｒｌ`、全角括号引号 | 逐字符做，输出多字符时全部映射回同一原始下标 |
| 3 | 行首壳剥除（可重复）：引用 `>`/`＞`、列表 `-*+•`、编号 `1.` `1)` `(1)` `一、`、shell 提示符 `$`/`#`/`PS>`、日志前缀（ISO/常见时间戳、`[INFO]`、`prog[123]:`） | 引用块、编号列表、日志粘贴 | 只剥**行首**，不触碰行内 `2>&1`、`>&`、`#!` |
| 4 | 围栏行（```` ``` ````）整行清空 | markdown 围栏 | 围栏行本身无能力 |
| 5 | 行内码反引号删除 | 行内码 | 无能力字符 |
| 6 | HTML：白名单标签名 `</?(code|pre|p|li|td|…)>` → 空格；实体解码（`&lt; &gt; &amp; &quot; &#39; &nbsp; &#x..;`） | HTML `<code>`、`2&gt;&1` | **不使用** `<[^>]+>` 通配，避免吃掉 shell 的 `<(curl …)`；实体解码是**加法**方向（`&gt;` → `>` 让 stdio 重定向可见） |
| 7 | JSON/YAML 转义还原：`\n`/`\t`/`\r` → 空格，`\"`→`"`，`\\`→`\`，`\/`→`/`，`\uXXXX`→字符 | JSON 字符串载体 | `\n`→空格而非换行：保持「一行 = 一处置单位」，JSON 行整体处置，不产生残片 |

**明确不做**的两个算子（否决记录）：

- **不删表格竖线 `|`**：`| curl -fsSL … \| bash |` 里删掉 `|` 会把管道 sink 一起删掉，
  等于自毁特征。表格载体本来就不需要删竖线——单元格内容 `curl … | bash` 原样即可命中。
- **不做整行通配 HTML 标签剥除**：见算子 6。

**归一化只用于「让特征更可见」，不用于「决定谁参与判定」**——这是与 R288 的本质区别。

## 3. 抽取环节彻底失效时的安全下界

设 `N(x)` 为归一化，`K(·)` 为能力聚合内核（`globalExecDangerReasonForSurface`：
`hasExecIntentReason` ∨ `fetchThenRunReason` ∨ 连续量打分 ≥ 3）。

判定：`hit(x) = K(N(x)) ∨ K(x)`。

- **下界 1（载体无关）**：`K(x)` 一项不含任何载体识别、不含任何抽取，
  输入是即将交付给用户的**完整原始字符串**。任何载体如果没有改变危险字面
  （加围栏、加编号、加表格竖线、加 HTML 标签、逐行包中文散文、插空行、跨段落、
  跨笔记，都不改变字面），`K(x)` 直接命中。R289 的**全部 12 种载体形态里，
  除全角化、零宽插入、JSON 转义、HTML 实体这四种「改字面」的形态外，
  其余 8 种在下界 1 上就已命中**（这四种由 §2 算子 1/2/6/7 覆盖，且它们是
  确定性字符级还原，不涉及「哪块是代码」的判断）。
- **下界 2（处置侧）**：`hit` 为真时，处置侧若**一个原始行都没定位到**
  （极端情形：归一化行与能力行不对应），则整篇答案替换为
  `ISOLATION_NOTICE_ANSWER`（降级窗口用 `EXEC_DEGRADED_ISOLATED_MARK` + 通知）。
  即「命中但定位不到」不会退化成「原样交付」，只会退化成「全篇隔离」。
  形式化：`hit ⇒ (定位到的原始行全部被处置) ∨ (整篇被替换)`，
  不存在第三个分支，因此 `hit ⇒ 危险字面不出现在无标记位置`。
- **下界 3（fail-closed 降级）**：判别器不可用/超时（`EXEC_CLASSIFY_BUDGET_MS`）时，
  `unavailable=true` 一律置 `exec_guard_degraded`（R289 P0-1 的 fail-open 就出在
  「没隔离到东西 ⇒ 不置标记」），且降级窗口的处置只有「隔离」一种形态。

实现：`globalExecDangerReason()`（并集）、`isolateNoteInstructions()` 的
`wholeAnswerFallback` 分支、`index.ts` 的 `exec_guard_degraded` 无条件置位。

## 4. 门控（送 LLM 判别的条件）

旧门控 `execClassifierGateReason` 的三个判据（代码单元长度、围栏正则、`execRiskScore`）
里前两个依赖载体识别 → R289 实测门控与兜底同时缺席。

新门控（`execClassifierGateReason`）：在**归一化全文**上，出现下列任一即开门：

1. 任一能力原语迹象：`execCapabilities` 的 net/exec/fetch/inline/lolbin/sink/shellio/priv/hostport
   任一为真，或 `EXECISH_RE`/`STDIO_RE`/`CONNECTISH*_RE`/`hasObfuscatedAddress`；
2. 存在代码类围栏（保留原判据，成本可忽略）；
3. 连续量打分 ≥ `EXEC_RISK_GATE_THRESHOLD`（1.5）。

判别器返回 `null`（不可用/超时/异常）→ `unavailable=true` → 保守隔离 + `exec_guard_degraded`。

成本：门控放宽后调用量上升，用三道闸控制——
(a) 每请求最多 1 次判别调用（既有）；
(b) 判定面缓存（§6，同一判定面 + 同一用户 10 分钟内不重复调用）；
(c) 纯自然语言问答（无任何原语迹象）门控关闭，延迟不变。
实测数字见 PR 描述「性能」节。

## 5. 偏移映射与 verbatim 两态互斥（P0-2 根因）

**映射**：归一化行 ↔ 原始行是双射（§2），处置区间一律取**原始行边界**
`[oStart, oEnd)`。因此：

- 隔离标记永远落在整行位置，不可能落在一条命令中间 → **不产生残片**；
- 判定用归一化文本（看得见特征），替换用原始文本区间（落点正确），
  两者不共享「哪块是代码」这一判断。

**两态互斥（原子化）**：R289 P0-2 的破法是「同一次答案里，一部分行走
『警示+原文』、一部分行走『隔离』」，读者拿到被挖掉几行的半截命令。收口：

```
verbatim 且判别器在线：
  1. 逐行算处置：官方安装源豁免行 → 警示+原文（分级处置，见 §7）
  2. 其余能力行 → 尝试从 dataText 精确切片还原
  3. 若**任一**能力行还原失败 → 本次答案的**全部**非豁免能力行统一改为整段隔离
  ⇒ 结果只有两态：全部「完整原文+警示」 或 全部「整段隔离」
非 verbatim：全部能力行 → 隔离标记（单态）
判别器不可用：全部能力行 → 降级隔离标记（单态）+ exec_guard_degraded
```

实现：`isolateNoteInstructions()` 中 `globalHit` 分支的 `atomizeVerbatim`。

## 6. 判定缓存重做（P0-3）

R289 实测：`FNV-1a 32bit(surface)+length` 6 字节 meet-in-the-middle 秒级构造碰撞，
先用良性面写入 `danger=[]`，危险面命中同键直接放行。

新设计（`answer-guard.ts`）：

1. **键**：`SHA-256(“r290v1” ‖ userId ‖ 0x00 ‖ 归一化判定面)` 全长十六进制（Web Crypto
   `crypto.subtle.digest`，Workers 运行时原生可用；`execSurfaceCacheKey` 改为 `async`）。
   32bit FNV 从安全判定路径删除。
2. **用户维度**：`userId` 进键，跨用户不复用（消除「他人写入影响我的判定」）。
3. **完整原文校验**：缓存条目**存储判定面全文**，命中时逐字符比较
   `stored.surface === surface`，不等即视为未命中。
   ⇒ 即使 SHA-256 被碰撞，攻击者仍需构造**判定面完全相同**的两段文本，
   而判定面相同意味着判定结论相同，攻击无收益。**碰撞攻击在设计上失效**
   （不依赖哈希强度，只依赖字符串相等）。
4. **不缓存「安全」结论的例外**：安全结论仅在通过 §6.3 的完整原文校验后复用，
   TTL 10 分钟且写入不续期（防「LRU 续期长期保活」）。危险结论同样校验。
5. 复跑 R289 的 meet-in-the-middle 构造，实测不再放行（`test/r290-cache.test.ts`
   + `scripts/r290-cache-collision.ts`）。

## 7. P1 事项口径

- **跨笔记能力聚合**：判定面 = 整篇答案（一次问答引用的全部笔记都渲染在同一答案里）
  ∪ `dataText`（全部被检索笔记的资料面拼接）。因此「笔记 A 建连 + 笔记 B 执行」
  天然是同一判定面上的能力聚合，不需要额外的跨笔记逻辑；处置侧对两条笔记
  各自的能力行同时处置（R289 的「只隔离其中一条」是抽取漏面的次生现象）。
- **官方安装脚本误伤分级**（不放宽下界）：
  - 警示 + 保留原文：命中 `installerBenignText`（官方安装源白名单：`sh.rustup.rs`、
    `raw.githubusercontent.com/Homebrew/install`、`get.docker.com`、`deb.nodesource.com`…）
    **且**全文无以下任一：外连回调（`hostport` ∧ (`net` ∨ `shellio`)）、
    混淆地址、stdio 接管、反弹 shell 字面、LOLBin。
  - 整段隔离：以上任一命中，或来源不可核（答案里的命令去 URL 折叠后
    不是资料侧某个「本身即官方安装法」代码单元的子串）。
  - 上游外链收口把 URL 换成标记后，来源证据回落到 `dataText`（R288 P1-1 已有，
    R290 扩展为「归一化后再比对」，修 R289 的 Rust/Homebrew 2/30）。
- **财务时间窗/极值按事件时间**：时间窗与极值改用「笔记内容中的事件日期」
  （`3月10日`/`3/10`/`2026-03-10` 等），无内容日期时回退 `created_at`。
- **`execcls` 可观测性**：判别耗时在响应头写出前入 `askMarks`（R289 实测头先于
  finalize 外发导致该项永不出现）。
- **SSE 真流式**：见 PR 描述实测节。
- **退款方向**：退款是「支出的减项」，不计入收入。
