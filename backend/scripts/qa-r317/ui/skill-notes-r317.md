## R317 copy-guard (exec-guard.tsx CopyGuard/PageCopyGuard) testing
- Clipboard canary method works well: `printf CANARY-R317 | DISPLAY=:0 xclip -selection clipboard` → perform the copy action in the UI → `DISPLAY=:0 xclip -selection clipboard -o`. "Cancel keeps canary / 仍要复制 replaces it" is the assertion; take the screenshot while the ConfirmDialog is open (titles: 「复制破坏性命令？」/「复制口令/密钥类内容？」/「复制命令/代码形态内容？」).
- A credential-shaped note (e.g. 「跳板机口令是 Qv8#mk3zz」) is likely to be triaged `is_sensitive:true` even with `skip_triage:true`, so it renders as the SENSITIVE card (「敏感」badge + `••••` + 「敏感内容，点击查看」) — NOT the exec-guard credential fold — and has no `[data-copy-guard]`; all copy paths after reveal may go through unguarded. Check `GET /api/notes` `is_sensitive` first so you can attribute the behaviour to the right code path, and note that sensitive notes never enter Ask (「没找到相关笔记 … 提示：账号密码这类信息如果记成了加密的敏感笔记，内容不会进入问答」), so the `〔凭证略…〕` placeholder cannot be exercised with them.
- Clicking (desktop) or long-pressing (CDP touch, ~900ms) a note card's body enters inline-edit mode (textarea) — inputs are whitelisted by PageCopyGuard, so Ctrl+A/Ctrl+C there copies the raw dangerous text with no confirm. Include this in bypass attempts.
- Code-level (③) prompts differ by path: menu 复制内容 → blocking ConfirmDialog, selection Ctrl+C/right-click → inline hint only (CODE_COPIED_HINT). Record it as a consistency observation.
- DevTools `copy()` via CDP `Runtime.evaluate {includeCommandLineAPI:true}` does NOT touch the system clipboard (needs the real DevTools frontend); use F12 → Console and type `copy("...")` (ASCII only) to demonstrate the browser-native bypass.
- CDP touch long-press: `Emulation.setTouchEmulationEnabled{enabled:true}` + `Input.dispatchTouchEvent touchStart` → sleep → `touchEnd`; it does not produce a system selection menu on this box, so real-device long-press-copy stays 【未验证】.
