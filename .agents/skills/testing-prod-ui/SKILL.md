# Testing suinian production Web UI

- Prod Web: https://suinian.zalize.com, API: https://suinian-api.zalize.com. Cloudflare blocks non-browser UAs; use a real browser (or curl with a Chrome UA) for API calls.
- D1/wrangler auth: the session shell env already exports a working `CLOUDFLARE_GLOBAL_API_TOKEN` — run `CLOUDFLARE_API_TOKEN="$CLOUDFLARE_GLOBAL_API_TOKEN" npx wrangler d1 execute ...` from `backend/` using the shell's existing env. Binding the org secret via the exec tool's `env` param may inject a stale token that fails with 7403; prefer `${!var}` expansion of the pre-set env vars (CLOUDFLARE_WORKERS_API_TOKEN also works).
- Graph schema: `edges` has `src_type/src_id/dst_type/dst_id/relation/note_id` (no `entity_id` column); `entities` has `user_id,name,type,aliases`. For sensitive-plaintext sampling: create a note with a unique marker word that triggers auto-sensitive, then check `entities.name/aliases LIKE '%marker%'` = 0 and `edges` joined on the sensitive note's id = 0; the same account's non-sensitive notes should have entities (positive control).
- Sensitive export (设置 → 导出数据): checking 包含敏感内容 then clicking any export button opens a `window.prompt` password dialog. Cancel aborts without a request; empty string submits and the backend returns the readable error 「导出敏感内容明文需要验证账号密码：请输入密码后重试」; wrong password → 「密码不正确，请重新输入」. Error text renders below the export buttons (may need to scroll).
- Android emulator prod testing: install via `sdkmanager "emulator" "system-images;android-34;google_apis;x86_64"` then `avdmanager create avd -d pixel_5`; needs `sudo chmod 666 /dev/kvm`（passwordless sudo 可用）. Chinese input into the emulator: host `xclip -selection clipboard` 后点 Gboard 剪贴板 chip（adb `input text` 仅 ASCII；宿主 ctrl+v 单独无效）。App 包名 `com.zalize.suinian`；App 内注销路径：设置 → 危险操作 → 永久注销（输入「注销」确认）。
- Bulk perf seeding: POST /api/notes with `skip_triage:true` at ~1.15s intervals stays under the 60/min write limit (520 notes, zero 429s). skip_triage notes land with category=idea, so finance-stat ask questions won't count them; ask on a finance-stats question hits the deterministic path (~0.2s), use a semantic question to exercise the AI path (~6.5s).
- QA accounts: register throwaway accounts via 设置 → 账号 → 注册/登录 (username + password, recovery code shown once). Report any created accounts to the user for cleanup. Never touch u_boss or real accounts.
- Chinese input via computer-use `type` may fail; write text to clipboard instead: `printf '中文' | xclip -selection clipboard` then Ctrl+V in the page.
- `read_dom`/`browser_console` may attach to the wrong Chrome window if multiple are open — check `wmctrl -l` and close extras.
- Ask streaming (R174/R176): citations `[n]` are plain text while streaming and become clickable after `done`. Verify markers are separate elements and citation count matches max marker index.
- Sensitive notes: masked by default with `aria-label="敏感内容，点击查看"` button; click reveals plaintext + 隐藏 button.
- Cache identity (R166): cache name `suinian-api`, key param `sn_uid=<first 8 bytes of sha256(token) as hex, i.e. 16 hex chars>`. Cache *writes* come from the Service Worker, but the scrub (`scrubApiCacheForToken`) is app-level (main.tsx load + token change). If prod SW is stuck installing (seen: "#0 trying to install", settings page shows 离线缓存正在安装中), you can still test the scrub by manually seeding an entry via `caches.open('suinian-api').put(url?sn_uid=<fp>)` in console, switching accounts in the UI, and asserting the old-fp entry is deleted.
- Lighthouse: `npx lighthouse https://suinian.zalize.com --chrome-flags="--headless=new" --output=json` (add `--preset=desktop` for desktop). Works headless despite Cloudflare.
- `backend/scripts/triage-eval.ts` against prod WILL hit the 60/min write rate limit (79 cases posted back-to-back) and abort with 429 mid-run. Temporarily patch the POST loop with a ~1.1s inter-post sleep + retry-on-429 (sleep 20s) before running, and revert the patch afterwards (`git checkout backend/scripts/triage-eval.ts`). Also wait ~70s after any prior burst of note writes on the same account before starting the eval.
- Post-deletion residue check: after `DELETE /api/auth/me`, verify with `CLOUDFLARE_API_TOKEN="$CLOUDFLARE_GLOBAL_API_TOKEN" npx wrangler d1 execute suinian --remote --json --command "SELECT (SELECT COUNT(*) FROM users WHERE id IN (...)) AS users, (SELECT COUNT(*) FROM notes WHERE user_id IN (...)) AS notes"` — both should be 0.
- Auth API: login response token field is `api_token` (not `token`); account deletion is `DELETE /api/auth/me` → `{"ok":true}`, after which the token returns 401.
- Settings appearance has theme options (浅色/深色/跟随系统) plus a 字号 control (小/标准/大/特大) as of R195.
- PWA / Service Worker testing (R194/R195):
  - Page-level `page.route('**/sw.js*')` does NOT intercept the SW script fetch (it bypasses the page network stack). Use a browser-level CDP session: `browser.newBrowserCDPSession()` + `Fetch.enable {patterns:[{urlPattern:'*sw.js*'}]}` + `Fetch.failRequest`. Unregister the existing SW first, then hard-reload to trigger `onRegisterError` → banner 「离线缓存不可用（Service Worker 注册失败）…」.
  - Offline emulation via `Network.emulateNetworkConditions {offline:true}` only lasts while the CDP session is attached — keep the node process alive (setInterval) and restore online on SIGTERM. Verify with `navigator.onLine === false` + failing fetch before testing.
  - After a simulated sw.js block, Chrome's SW registration job queue can wedge for the profile: `register()` never resolves, the app's 重试安装离线缓存 button spins forever, and clearing Storage/hard reload/browser restart don't help. Recovery: kill Chrome, `rm -rf '<user-data-dir>/Default/Service Worker'`, relaunch (login in localStorage survives).
  - Offline image outbox: uploading while offline shows 「1 条离线记录（含图片/文件/录音）待同步，联网后自动补发」 under the quick input; going back online auto-resends without user action. The banner doubles as a manual retry button (点击立即重试同步).
- This test box's browser network to the prod API intermittently hangs ~60s per request (status 0) while curl succeeds in 0.2s — retry the UI action or use the outbox retry banner; don't misattribute it to prod. Search and initial timeline load hit this too: after the hang the UI shows 「网络连接失败，请检查网络后重试」 with a 重试 button that recovers on click.
- To store a QA account's token without printing it: 设置 → 账号 → 「复制我的 API token」 (button flips to 已复制), then pipe the clipboard straight into a file/env: `TOKEN=$(DISPLAY=:0 xclip -selection clipboard -o) python3 -c ...`.
- Right after an outbox auto-flush, an offline-queued image note's card may transiently show 「原图加载失败，可稍后刷新重试」; a normal online F5 renders the original image fine (verified R209) — record it as a transient, not a prod defect, unless it persists across refreshes.
- Offline (CDP `offline:true`, session kept alive) verified end-to-end in R205: text note AND image upload both queue into the outbox (banner counts 「N 条离线记录…待同步，联网后自动补发」); an offline F5 reload still renders the cached timeline with the banner intact; restoring online (kill CDP session + explicit `offline:false`) auto-resends within ~10s and the notes get real server triage (image note becomes 资料/图片识别). Note: queued offline notes do NOT appear as pending cards in the timeline — only the banner shows them.
- Slow-network mutation testing: R206 added a pending state to the sensitive toggle (`sensitivePendingIds` in timeline.tsx) — during an in-flight PATCH the card badge shows 「取消敏感中…/标记敏感中…」 with a spinner and the menu item is disabled showing 「更新中…」; spam clicks fire 0 extra PATCHes (verified R207 on prod with 5s latency). Count PATCHes by monkey-patching `window.fetch` before clicking. Use ≥5s latency: with 2s the PATCH completes between computer-use clicks and a re-click becomes a *legitimate second toggle* (2 PATCHes for 2 intents), which is easy to misread as a dedup failure — log PATCH timestamps+bodies to tell them apart.
- The `browser_console`/`read_dom` tools may fail with "Could not connect to Chrome via CDP" even when Chrome's debug port (29229) is up. Fallback: drive CDP yourself with python `websockets` (available on the box) — a Runtime.evaluate one-shot script and a Network.emulateNetworkConditions keepalive script cover eval + network shaping (see /home/ubuntu/qa-r207/cdpeval.py, cdpnet.py pattern).
- CDP network emulation can silently drop mid-test (session reset → navigator.onLine flips back to true and requests succeed): don't apply once and trust it — reapply `Network.emulateNetworkConditions` every ~3s in a keepalive loop, and re-verify `navigator.onLine`/probe-fetch right before the action under test. The python `websockets` keepalive itself can die with `1011 keepalive ping timeout` (Chrome doesn't answer WS pings while busy): open the connection with `ping_interval=None`, read/drain each command ack, and wrap the loop in a reconnect-on-failure retry (see /home/ubuntu/qa-r209/cdpnet2.py). Consequence of a lapse: the outbox auto-flush WILL sync queued notes during the gap, so a "banner count increments to N" assertion can be defeated — verify queue *contents* by expanding the banner (queue preview lists entries like 「[图片] testimg.png」) instead of relying on the count alone.
- Slow-network *first-load* tests are defeated by the SW: cached app shell + cached /api/notes render instantly, so the NoteListSkeleton never shows. To observe the skeleton on prod, first `r.unregister()` all SW registrations + `caches.delete()` all caches, then hard-reload under latency-only emulation (5s works); the skeleton (3 gray pulse cards, role=status aria-label=加载中) shows for ~5-10s with NO timeout/hint text (R205 P3-4 observation still true as of R207). The SW re-registers itself on the next normal load, no manual repair needed.
- Chrome (Devin-managed, port 29229) can crash mid-session; relaunch with `DISPLAY=:0 google-chrome --user-data-dir=/home/ubuntu/.browser_data_dir --remote-debugging-port=29229 --no-first-run --hide-crash-restore-bubble <url>` — the localStorage login survives. Re-maximize and dismiss the Google Translate popup (its X steals the first click).
- Mapping CDP CSS-px coords → computer-use tool coords (screen 1600x1200 scaled to 1024x768): tool_x = css_x * 0.64, tool_y = (css_y + (outerHeight-innerHeight)) * 0.64 with the window maximized at (0,0). Compute button centers via getBoundingClientRect in Runtime.evaluate, then click those tool coords.
- TriageBacklogBanner (R206 P3-1) needs ≥5 *loaded* notes with `category === null && meta.imported_at != null` AND a nonzero /api/stats pending count — not triggerable on a small QA account without a real bulk import; mark untested unless you're prepared to import a crafted backup.
- Font size control asserts: 小/标准/大/特大 map to root font-size 14/16/18/20px (`localStorage['suinian.fontsize']` = small/normal/large/xlarge); changing it reflows the settings page, so re-query button coords after each click.
- Devin-managed Chrome runs on DISPLAY=:0 with `--user-data-dir=/home/ubuntu/.browser_data_dir` and `--remote-debugging-port=29229`; if you must restart it, reuse the full original command line (`cat /proc/$(pgrep -f remote-debugging-port)/cmdline | tr '\0' ' '`) so CDP tools keep working, and re-maximize with `DISPLAY=:0 wmctrl -r :ACTIVE: -b add,maximized_vert,maximized_horz`. When relaunching, do NOT join the cmdline into one shell string (args with spaces get re-split and the URL/UA break into extra tabs): split `/proc/<pid>/cmdline` on NUL into an argv list and `subprocess.Popen(argv)`.
- SW auto-retry recovery (R202: 30s/60s/120s re-register after failure) CAN be proven end-to-end (done in R203) if you never let the wedge happen: use a brand-new `--user-data-dir` per run, attach `browser.newBrowserCDPSession()` + `Fetch.enable{urlPattern:'*sw.js*'}`, `Fetch.failRequest` the first two fetches, then `Fetch.continueRequest` (or disable the pattern) *before* the next retry tick. Observed timeline: t+0 fail → banner + beacon `retry:0`; t+30s fail → beacon `retry:1`; unblock; t+60s fetch succeeds → banner disappears and `navigator.serviceWorker` reports `active:true`. If the queue still wedges, `rm -rf '<user-data-dir>/Default/Service Worker'` and start over rather than reporting inconclusive.
- SW beacon rate limit (`POST /api/metrics/sw-error`, public): exactly 5×200 then 429 per IP per minute. Fire the burst from inside the page with `fetch` so the Cloudflare-acceptable browser UA is used, and wait ~65s after any earlier beacons so the window has reset.
- If Chrome died and you need a logged-in QA account's token (e.g. to `DELETE /api/auth/me`), recover it from disk: `strings '~/.browser_data_dir/Default/Local Storage/leveldb/'*.log | grep -o 'apiToken[^,]*'`. Always verify with `GET /api/auth/me` before deleting.
- ask-eval (backend/scripts/ask-eval.ts): run under `nohup ... > log 2>&1 &` — if the launching shell dies mid-run the eval account (random UUID password, unrecoverable) is orphaned. To clean an orphan, mirror `backend/src/account.ts` deleteUserData via `wrangler d1 execute --remote` (NOTE_ID_TABLES by note_id subquery, USER_ID_TABLES by user_id, auth_rate_limits `%:<userId>` / `%:acct:<name>` with `_` escaped, then users). Vectorize binding is commented out in prod wrangler.toml, so D1-only cleanup is complete. Expect intermittent `429 rate-limited on /api/ask` with auto-retry; a full run takes 30-60+ min.
- Web 注销 (account deletion, 设置 → 危险操作): the confirm input rejects computer-use `type` for Chinese — set it via React-safe native setter in console (`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set.call(inp,'注销'); inp.dispatchEvent(new Event('input',{bubbles:true}))`). The first 永久注销 click may fail with 「请求超时，请重试」 while the backend cascade is still running; just retry — the second attempt completes and the app logs out to the welcome screen. Verify with the saved token → `GET /api/auth/me` = 401.
- D1 compound SELECT has a low term limit ("too many terms in compound SELECT" ~ >8 UNION ALL); for multi-table residual checks send semicolon-separated statements in one `--command` with `--json` (returns one result block per statement).
- If no X server / computer-use is available, headless Playwright (`NODE_PATH=web/node_modules node script.js` with `chromium.launch({executablePath:'/home/ubuntu/.local/bin/google-chrome', headless:true})`) drives the full prod UI flow fine. Gotchas: onboarding modal → click 「注册新账号」 text; register submit button is 「注册并开始使用」 (not type=submit); recovery-code card needs last-4 chars into 「输入恢复码末 4 位确认已保存」 then 「我已安全保存，继续」; re-registering an existing name+password is idempotent and skips the recovery card (goes straight in); `getByLabel('快速记录')` matches 2 elements — use `.first()`; alternatively seed `localStorage['suinian.settings']` via `addInitScript` with `{apiBaseUrl, apiToken, useMock:false, onboarded:true, tourSeen:true}` to skip auth UI entirely. Ask via `?`-prefixed quick input; capture answers from `document.body.innerText` + screenshots.

- D1 schema gotchas for residual/orphan checks (R203): `users` has `name`, NOT `username`; `attachments` has only `(id, note_id, r2_key, mime, size)` — join to `notes` to scope by user; `note_embeddings` and `wecom_kf_state` have no `user_id` column (scope by `note_id` / other keys). Full table list is 22 tables + `auth_rate_limits`. Get the account id for the D1 HTTP API with `GET /client/v4/accounts` using `CLOUDFLARE_GLOBAL_API_TOKEN`; the prod `database_id` is in `backend/wrangler.toml`. After `DELETE /api/auth/me` the cascade is clean: 0 rows in every user-scoped table, 0 orphans, and `attachments` rows for the deleted user's notes are gone too. `auth_rate_limits` legitimately keeps a handful of TTL rows (login/beacon buckets) — that is not residue.
- Write rate limit (`note_write`, 60/min/user) will NOT trigger from a serial curl loop (each request takes ~1.5s so 60 requests span >1 min). Use a parallel burst: `seq 1 80 | xargs -P 20 -I{} curl ... -d '{"content":"...","skip_triage":true}'` → mix of 201/429. `skip_triage:true` avoids burning AI quota. Note the POST body field is `content` (not `text`); wrong field returns 400.
- Category expectations when scoring triage accuracy: link/bookmark notes are `collect` (the enum is `idea|todo|collect|data|expense|income|transfer`) — there is no `link` category. Don't score `collect` as an error.
- Web visual walkthrough (R223): timeline note cards have no click-through detail page; the detail/edit surface is the card's 更多操作 (…) menu → 编辑 inline form (close with 取消 for read-only checks). Font sizes live in 设置 → 外观 (小/标准/大/特大 → root 14/16/18/20px, localStorage `suinian.fontsize`). For mobile-layout checks, DevTools responsive mode (F12 + Ctrl+Shift+M, type width/height in the toolbar) works on the Devin-managed Chrome; assert no horizontal overflow via `document.documentElement.scrollWidth === window.innerWidth`.

## Android emulator prod testing (R203)
- Build: `cd android && echo "sdk.dir=$HOME/android-sdk" > local.properties && ./gradlew assembleDebug`; APK at `android/app/build/outputs/apk/debug/app-debug.apk`. Launch activity is `com.zalize.suinian/.ui.MainActivity` (NOT `.MainActivity`) — resolve it with `adb shell cmd package resolve-activity --brief com.zalize.suinian`.
- Emulator needs `/dev/kvm` access and must run headless (`-no-window`) if there is no usable X server.
- CRITICAL: do not leave a `adb shell wm size <small>` override in place. With a squashed viewport the registration screen's submit button silently does nothing; `adb shell wm size reset && adb shell wm density reset` made 注册并开始使用 work immediately. If a form button appears dead, check `wm size` first.
- `adb shell input text` breaks on spaces — use `%s` for each space. Literal `[` / `]` typed fine inside single quotes on API 34 (`input text '[QA-R204]-and'`), but text after the first space is dropped, so combine: `'[QA-R204]%staxi%sto%sairport'`. CJK text throws NPE — install ADBKeyboard (`curl -sL -o /tmp/ADBKeyboard.apk https://github.com/senzhk/ADBKeyBoard/raw/master/ADBKeyboard.apk; adb install -r ...; adb shell ime enable com.android.adbkeyboard/.AdbIME; adb shell ime set ...` — retry the enable if it says Unknown input method right after install), then `adb shell am broadcast -a ADB_INPUT_TEXT --es msg '注销'`. Restore with `ime set com.google.android.inputmethod.latin/com.android.inputmethod.latin.LatinIME`.
- Bottom-nav tab taps DO switch pages (verified R204 with both static-coordinate taps and per-tap uiautomator dump → node-center taps on all 5 tabs at 1080x2400): the r203 report of dead tabs was a false alarm, most likely caused by a leftover `wm size` override or a slow/ANR emulator. If tabs seem dead, check `wm size` and System UI ANR first. Fallback: reach 问答 by sending a `?question` through the quick-input box.
- Attachment upload: home → `更多入库方式` (content-desc) → 相册选图入库 → pick a photo pushed with `adb push file /sdcard/Download/x.png` + MEDIA_SCANNER_SCAN_FILE broadcast. Success shows a 分拣中 / 图片识别 card and 「已上传，AI 正在识别图片内容」.
- Emulator stability: qemu-system-x86 is the first OOM-kill victim on this 8GB box (killing it can take X/Chrome down too). Add swap first (`sudo fallocate -l 4G /swapfile; sudo chmod 600 /swapfile; sudo mkswap /swapfile; sudo swapon /swapfile`) and start with `-memory 2048 -gpu swiftshader_indirect`. Suppress recurring System UI ANR dialogs (they swallow taps/typing) with `adb shell settings put global hide_error_dialogs 1`.
- Toast verification (e.g. OnboardingScreen empty-password Toast): tap the button then burst `adb exec-out screencap -p` in a loop (~1/s catches a LENGTH_SHORT toast) and confirm via `adb logcat -d | grep -i toast` (look for `Window{... u0 Toast}` from the app pkg). Beware: after the inline error text appears the button shifts down — re-run `uiautomator dump` and recompute the node center before the second tap, or the tap misses silently.
- To recover the Android account token for cleanup: `adb shell "run-as com.zalize.suinian cat /data/data/com.zalize.suinian/files/datastore/settings.preferences_pb"` and extract the longest hex run — it has ONE extra leading protobuf byte, so strip the first character (valid token is 48 hex chars). Verify with `GET /api/auth/me` before `DELETE /api/auth/me`.

## Android manual clipboard paste (R215)
- To paste into an Android EditText via a GENUINE long-press → Paste popup (e.g. to rule out `adb input text` artifacts): put the text on the HOST clipboard (`xclip -selection clipboard -d :0`), then give the emulator window REAL focus (a computer-use click on its title bar — `wmctrl -a` alone is NOT enough; verify sync with `adb shell dumpsys clipboard | grep -c <substr>`), long-press the field via `adb shell input swipe X Y X Y 1000`, and confirm the Paste bubble via `adb exec-out screencap -p` (the popup does NOT appear in `uiautomator dump` — locate it in the screenshot crop and `input tap` its device coords). After tapping Paste, verify via uiautomator dump: a masked token field shows N • chars matching the token length (48).
- `adb shell cmd clipboard set-text` is unsupported on API 34 ("No shell command implementation"), and the majido/clipper helper APK fails to install (INSTALL_FAILED_DEPRECATED_SDK_VERSION, targets SDK 0) — host-clipboard sharing + real window focus is the working path.
- R215 verdict: token login with a genuinely-pasted token WORKS on prod (R214 "token login fails" was an adb input artifact). Smoke CJK note paste also works with host clipboard + `input keyevent 279` after focusing the capture box.
- Devin-managed Chrome (port 29229) can crash mid-session; relaunch by rebuilding the exact argv list (see the /proc cmdline note above) with `subprocess.Popen` under DISPLAY=:0 — localStorage state survives. After relaunch the first page may render blank ("Untitled"); one F5 fixes it.
- Day1 timings measured R215 (fresh account, prod): /api/auth/register ~1.0s, POST /api/notes ~0.2s, triage badge ~8s, /api/ask ~1.5s. Useful as regression baselines.

## Devin Secrets Needed
- `CLOUDFLARE_GLOBAL_API_TOKEN` (D1 HTTP query API for read-only residual/orphan checks)
- QA accounts themselves are self-registered (no secret needed)
